# 간편 입력 / 상세 입력 스위치 — 설계 메모

- 출처: 사용자 대화(ChatGPT와의 토론 복붙), 2026-08-29 정리.
- 상태: **미착수.** 아래 내용 중 코드로 존재하는 것은 없습니다.
- 관련: `docs/agent-change-log.md`(구현 기록), `MOOA_RESUME_PROJECT_SPEC.md`(상품 정의).

---

## 한 줄 요약

**입력은 ChatGPT처럼 자유롭게, 그 뒤는 무아가 알아서 분류하고 채용 프로세스로 분석.**
입력 화면을 독특하게 만드는 것은 차별점이 아닙니다. 차별점은 **던져 넣은 뒤에 일어나는 일**입니다.

## 스위치

PRO/FINAL 첫 화면 상단에 아주 작게:

```
간편 입력 ● ── ○ 상세 입력
```

- **기본값은 간편 입력.**
- 안내 문구: `입력 방식만 다르고 첨삭·분석 수준은 동일합니다. 간편 입력에서는 자료를 한 번에 넣으면 자동으로 분류합니다.`
- 내부로 들어오는 데이터는 **양쪽이 완전히 같습니다.** 차이는 분류를 누가 하느냐뿐입니다.
  - 간편 = 무아가 자동 분류
  - 상세 = 사용자가 직접 분류 (지금의 `ProInputPage` 유지)

## 간편 입력 화면

큰 네모 **하나**.

```
지원 자료를 한 번에 넣어주세요

자기소개서 내용을 직접 입력하거나 붙여넣으세요.
파일은 이 영역에 드래그하거나 선택할 수 있습니다.

📎 파일 추가
PDF · DOCX · TXT · 이미지 · ZIP 등
```

## 다음 화면이 진짜 제품인 부분

업로드 직후 **분류 결과를 보여주고 고칠 수 있게** 합니다.

```
자료를 정리했습니다.

채용공고 · 1개
자기소개서 · 1개
이력서 · 1개
경력/경험자료 · 1개
기타 증빙 · 7개

[분류 수정]  [이대로 분석]
```

## QUICK은 반대 방향으로 단순화

| | 받는 것 | 문구 |
|---|---|---|
| QUICK | **파일 1개** 또는 붙여넣기 | `자기소개서가 포함된 파일 1개를 올려주세요. 이력서와 자기소개서가 하나의 입사지원서로 합쳐져 있어도 괜찮습니다. QUICK에서는 자기소개서 영역만 분석합니다.` |
| PRO/FINAL | 여러 파일 + ZIP | `지원 자료를 한 번에 넣어주세요` |

UI는 거의 같고 **받아주는 범위만** 다릅니다. 상품 차이가 화면에서 바로 보입니다.

## 비용 방어 — 이 기능의 진짜 위험

### 원칙

**OpenAI에 보내기 전에 서버에서 걸러야 합니다.**
20장짜리 이력서를 다 보내놓고 프롬프트로 "이력서는 보지 마"라고 쓰면 **이미 토큰 비용은 나간 뒤**입니다.

### 한도

| 항목 | 사용자에게 표시 | 내부 제한 |
|---|---|---|
| 파일 수 | 최대 20개 | ZIP 해제 후에도 20개 |
| 총 업로드 용량 | 50MB | 50MB |
| 파일 1개 | 표시 안 함 | 25MB |
| 총 페이지 | 표시 안 함 | 100페이지 전후 |
| 추출 텍스트 | 표시 안 함 | 20~30만 자 |
| ZIP | `지원` | 압축 해제 크기 제한 + zip bomb 차단 |
| 중복 파일 | `자동 제외` | hash 비교 |

QUICK은 따로: **파일 1개 / 10MB / 20페이지 / 3~5만 자.**

**개수 제한만으로는 부족합니다.** 자소서 여러 개를 PDF 하나로 합쳐 올리는 사람을 막으면 안 되므로, 파일 수가 아니라 **실제 내용량**을 봐야 합니다.

**"파일 개수 제한 없음"은 쓰지 않습니다.** 써 버리면 ZIP에 300개를 넣어도 약속한 셈이 됩니다. 화면에는 이 정도만:

```
최대 20개 · 총 50MB까지 한 번에 업로드할 수 있습니다.
ZIP 압축파일도 지원하며, 중복 파일은 자동으로 제외됩니다.
```

**한도를 넘겨도 통째로 거절하지 않습니다.** 130페이지 PDF라면:

```
문서가 분석 권장 범위를 초과합니다. 핵심 지원자료를 우선 분석할까요?
```

### 결제 전 / 후 나누기

**결제 전 (외부 API 비용 0원, 서버 연산만):**
파일명 · 확장자 · 크기 · ZIP 내부 목록 · 중복 hash · PDF 페이지 수 · TXT/DOCX 텍스트 추출 · 빈 파일 확인

→ `7개 파일 확인 / 총 18.6MB / 지원 가능한 형식 / 중복 1개 자동 제외` 까지는 **무료로 보여줘도 됩니다.**

**결제 후 (비용 발생):**
HWP/HWPX 변환 · 스캔 PDF/이미지 OCR · LLM에게 문서 종류·중요 페이지 판단시키기

기존 설계의 `결제 전에는 브라우저에서만 읽고 OpenAI를 호출하지 않는다`와 같은 방향입니다.

### 순서

```
① 한 박스에 전부 넣기
② Pre-check (무료)
③ 결제
④ 본격 문서 처리 (HWP 변환 / OCR / 파싱)
⑤ 자동 분류
⑥ 필요한 정보만 AI 분석
```

---

## HWP

- **ChatGPT 제품에서 HWP가 읽혔다고 해서 OpenAI API가 읽는 것은 아닙니다.** 공식 지원 확장자 목록에 HWP/HWPX는 없습니다. 제품 사양으로 의존하면 안 됩니다.
- Upstage Document Parse는 `.hwp`, `.hwpx` 업로드와 자동 변환을 **공식 지원**합니다.
- 가격(메모 시점): Document Parse Standard $0.01/page, Enhanced $0.03/page, 단순 OCR $0.0015/page.
- **모든 파일에 비싼 Parse를 쓰면 안 됩니다.** 라우팅:
  - TXT/DOCX → 자체 추출
  - 텍스트 PDF → 자체 추출 우선
  - HWP/HWPX → Upstage
  - 스캔 PDF/이미지 → Upstage OCR/Parse

## 압축파일 표기

- 초기에는 **`ZIP 압축파일도 지원`**이라고만 씁니다.
- `알집`은 쓰지 않습니다. 한국에서 그 말은 `.alz`, `.egg`까지 포함하는 것으로 읽히는데, **실제로 그 확장자를 처리할 수 있게 된 뒤에** 써야 합니다.

## 문구 후보

**입력 화면**

> 서류 준비, 이제 하나씩 넣지 마세요.
> 자기소개서도, 이력서도, 채용공고도 한 번에.
> 작성한 내용을 그대로 붙여넣거나 가지고 있는 지원 자료를 한 번에 올려주세요.
> 여러 파일을 하나씩 구분할 필요도 없습니다. 무아레쥬메가 자료를 자동으로 확인하고 분류한 뒤 필요한 내용을 함께 분석합니다.
> **넣는 건 한 번. 분석은 필요한 만큼 깊게.**

**메인/포스터 (더 짧게)**

> 지원자료, 그냥 한 번에 넣으세요.
> 자소서 복붙부터 이력서·경력기술서·채용공고까지.
> 여러 파일도, 압축파일도 한 번에 올리면 무아가 알아서 정리하고 분석합니다.

**광고 카피 대안**

> 파일만 넣으세요. 지원서 정리는 무아가 합니다.

## 왜 ChatGPT와 같아 보여도 괜찮은가

입력창만 보면 비슷해집니다. 그게 문제가 아닙니다.

```
ChatGPT:  📎 첨부 → "무엇을 도와드릴까요?"

무아레쥬메: 📎 첨부
            ↓ 자동 문서분류
            ↓ 공고 요구조건 추출
            ↓ 지원자 경험 추출
            ↓ 공고 ↔ 경험 매칭
            ↓ 문항별 경험 배치
            ↓ 15초 심사
            ↓ 누락 / 충돌 / 감점요소
            ↓ 최종 첨삭
            ↓ 제출 준비도
            ↓ 예상 면접 질문
```

**차별점은 "파일 첨부"가 아니라 "아무렇게나 던져도 취업 자료로 정리되고, 필요한 것만 읽는다"입니다.**

## 구현 순서 (제안)

1. **서버 한도 + Pre-check** — 이게 없으면 나머지는 비용 사고입니다. UI 없이 먼저.
2. **QUICK 파일 1개 + 자소서 영역 탐지** — AI 없이 제목/문항 패턴(`지원동기`, `성장과정`, `성격의 장단점`, `입사 후 포부`, `직무역량` 등)으로 후보 영역을 잡고, 애매하면 사용자에게 페이지 선택.
3. **PRO/FINAL 간편 입력 화면** — 단일 박스 + 스위치.
4. **자동 분류 + 분류 확인 화면.**
5. **ZIP 해제와 안전장치.**
6. **HWP → Upstage 라우팅.**

## 아직 정하지 않은 것

- 자동 분류를 규칙으로 할지, 저비용 모델로 할지 (비용/정확도 실측 필요).
- 상세 입력을 언제까지 유지할지. 간편이 충분히 정확하면 상세는 접힌 옵션으로 밀어도 됩니다.
- Upstage 도입 시점. 초기에는 HWP를 `DOCX/PDF로 변환해 올려주세요`로 안내하고 미루는 선택지도 있습니다.

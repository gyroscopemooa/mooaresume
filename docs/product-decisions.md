# MOOA Resume 제품 결정 기록

## 2026-08-15 — 사용자 작성 단계와 결과 예시 구조

### 배경

사용자는 모두 완성된 자기소개서를 가지고 들어오지 않는다. 빈 문서에서 시작하는 사용자, 초안을 발전시켜야 하는 사용자, 제출 직전 검수가 필요한 사용자는 서로 다른 안내와 결과를 필요로 한다.

### 결정 1: 작성 상태와 상품 범위를 분리한다

첫 진입에서 사용자의 작성 상태를 묻는다.

1. **처음부터 작성**: 경험 발굴 → 추가 질문 → 문항별 소재 배치 → 개요 확인 → 검증된 사실만으로 초안 작성
2. **작성 중 개선**: 초안 진단 → 부족한 근거 질문 → 구조·소재 개선 → Before/After
3. **제출 전 점검**: 글자 수·맞춤법·문항 충족·경험 중복·자료 모순·공고 적합성 → 최종본

QUICK/PRO는 별도의 분석 범위다.

- QUICK: 지원서 중심
- PRO: 채용공고, 이력서, 경력기술서 등 자료를 함께 교차 분석

따라서 `처음부터 작성 + PRO`, `제출 전 점검 + QUICK` 같은 조합이 가능하다.

### 안전 원칙

- 빈 문서 사용자에게 임의의 경험으로 초안을 생성하지 않는다.
- `경험 확인 → 부족한 사실 질문 → 사용자 확인 → 초안 생성` 순서를 지킨다.
- 작성할 원문이 없는 상태에서는 준비도 점수를 표시하지 않는다.
- 점수보다 확인된 사실, 추가로 필요한 정보, 다음 행동을 먼저 보여준다.

### 결정 2: 결과 예시는 하나의 서사로 보여준다

헤더에 첨삭 전/후, 피드백, 대시보드를 각각 메뉴로 만들지 않는다. 상위 메뉴는 **결과 예시** 하나로 유지한다.

결과 예시 페이지의 순서:

1. 가상 지원자와 공고 맥락
2. 전체 진단 대시보드
3. 가장 중요한 피드백 3개와 근거
4. 첨삭 전/후 문장 비교
5. 무엇이 왜 달라졌는지 변경 근거
6. 확인이 필요한 사실과 AI 추가 질문
7. 실제 분석 시작 CTA

랜딩에는 위 콘텐츠 중 Before/After 한 세트와 핵심 피드백을 미리 보여주고, 전용 페이지로 연결한다.

### 표시 원칙

- 모든 예시 데이터에는 `샘플 결과` 라벨을 노출한다.
- 랜딩의 82점은 가상 지원서의 고정 광고·설명용 예시다.
- 사용자 결과 화면의 점수는 실제 분석 이후에만 표시한다.
- 실제 API가 연결되지 않은 데모 화면은 `데모 데이터`임을 숨기지 않는다.

### 권장 헤더

- 서비스 소개
- 이용 방법
- 결과 예시
- 요금
- 분석 시작

FAQ/Q&A는 초기에는 랜딩 하단 섹션으로 제공하고, 질문이 충분히 쌓일 때 별도 페이지로 분리한다.

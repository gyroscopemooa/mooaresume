# MOOA Resume — 랜딩 게스트 진입 및 로그인 시점 결정

> 결정일: 2026-08-15  
> 상태: 최신 대화 결정 요약  
> 동일 내용은 루트의 최신 Landing/Guest Flow Addendum을 우선한다.

## 목표

첫 화면에서 복잡한 유형·상품 설명을 강요하지 않는다. 사용자는 자기소개서를 바로 붙여넣거나 파일을 선택해 시작하며, 입력한 내용은 다음 단계로 유지한다.

## 권장 히어로

```text
좋은 문장보다,
합격을 위한 준비를 봅니다.

채용공고와 내 경험, 지원서 전체를 연결해
지금 가장 먼저 고칠 부분을 알려드려요.

[큰 자기소개서 입력창]
[PDF · DOCX · TXT 파일 선택]

[내 작성 단계 확인하기]

로그인 없이 시작 · 결제 전 AI 호출 없음
```

## CTA 원칙

- 기존 `내 지원서 진단하기`, `무료 진단하기` 버튼은 히어로 입력 영역으로 모은다.
- 결제 전 실제 AI 분석을 하지 않는다면 전체 정밀진단처럼 오해되는 문구를 사용하지 않는다.
- 무료로 제공하는 결과는 글자 수, 목표 분량 대비 작성률, 작성 단계 임시 추천 등 규칙 기반 범위로 제한한다.
- 정밀 내용 분석은 QUICK/PRO 선택과 결제 이후에 진행된다고 미리 알린다.

## 게스트 흐름

```text
랜딩 입력 또는 파일 선택
→ 브라우저 내부 텍스트 추출
→ 작성 단계 임시 확인
→ QUICK/PRO 추천
→ 상품 선택
→ 로그인
→ 게스트 입력을 사용자 ApplicationCase로 이전
→ 결제
→ 실제 AI 분석
```

## 로그인 정책

처음부터 로그인을 강제하지 않는다.

로그인 없이 가능:

- 텍스트 입력
- 브라우저 안에서 PDF/DOCX/TXT 읽기
- 작성 단계 임시 확인
- 상품 추천과 가격 확인
- 샘플 결과 체험

로그인이 필요한 시점:

- 실제 OpenAI 분석
- 결제
- ApplicationCase 영구 저장
- 원본 파일 서버 업로드
- 여러 기기에서 이어서 작성
- 결과 재열람과 재분석

## 로그인 전 데이터

- 텍스트와 추출된 파일 내용은 `sessionStorage`에 임시 보관한다.
- 결제 전에는 원본 파일을 서버나 Supabase에 업로드하지 않는다.
- 로그인 후 사용자 동의를 받고 ApplicationCase로 이전한다.
- 원본 파일이 필요한 경우 로그인 이후 비공개 Storage에 업로드한다.
- 민감한 원문을 로그나 분석 이벤트 속성에 포함하지 않는다.

## 신뢰 원칙

사용자가 오랫동안 작성한 뒤 처음 결제를 발견하게 만드는 숨겨진 Paywall은 사용하지 않는다. 입력 전에 로그인 없이 가능한 범위와 유료 정밀 분석 범위를 짧게 고지한다.

권장 안내:

```text
입력 내용은 이 브라우저에 임시 보관됩니다.
로그인하면 안전하게 저장하고 이어서 작성할 수 있어요.
정밀 AI 분석은 상품 선택 후 진행됩니다.
```

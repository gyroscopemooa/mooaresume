# 두괄식 작성 기준 (지원 동기 중심)

운영자(민수) 샘플 기준, 2026-10-22. 1차 첨삭 프롬프트(`src/server/ai/quick/prompt.ts`)와 추가 첨삭 프롬프트(`src/server/second-review/automatic-contract.ts`)의 두괄식 추천 규칙은 이 문서를 따른다. 규칙을 바꾸면 두 곳과 이 문서를 같이 고친다.

## 원칙

- 읽는 사람이 첫 문장만 보고도 "왜 지원했는지(무엇을 답하는지)"를 알게 한다.
- 결론 → 이유(첫째·둘째) → 입사 후 계획 순서.
- 이유 하나하나가 그 자체로 이유가 되어야 한다. "~라고 판단했습니다"처럼 근거 없는 판단으로 끝나면 안 된다. "~했기 때문입니다"로 근거까지 담는다.
- 뒤 이유가 앞 이유에서 나온 관심을 받는다면, 관심이 생긴 근거를 앞(첫째)에 둔다. "이러한 관심"이 소개되기 전에 나오면 안 된다.
- 원문 문장은 최대한 글자 그대로 옮기고 연결어만 더한다. 1차가 "좋은 표현"으로 표시한 문장은 반드시 그대로 둔다.
- 원문에 없는 이유는 만들지 않는다. 이유가 하나뿐이면 억지로 둘로 나누지 않는다.
- 결론으로 열고, 근거를 세우고, 결론으로 닫는다("이러한 이유로 ~에 지원하게 되었습니다"). 상담 노트(`docs/editing-philosophy-2-consultant-field-notes.md` §4-1)대로 마지막 재확인까지가 한 벌이다.
- 두괄식은 지원서 전체에서 한 문항, 많아야 두 문항만. 장점·단점은 적극, 경험·사례는 순서를 건드리지 않는다(§4-1).
- 적용 위치(2026-10-22 운영자 결정):
  - 1차 첨삭: 본문은 두고 "다른 시각 추천안"으로 두괄식 전체를 제시한다.
  - 추가 첨삭: 완성된 두괄식은 본문(첨삭 후·최종 첨삭본)에 적용하고(disposition alternative), 그 문항의 추천안에는 다른 두괄식 스타일(예: 번호 없이 한 문장으로 이유를 먼저 말하는 첫 문장)을 준다.

## 운영자 원본 샘플 (2026-10-22, ISC Tech R&D 지원 동기)

```
제가 ISC Tech R&D에 지원한 이유는 두 가지입니다.

첫 번째, 테스트 소켓 분야에서 신규 구조 개발, 신뢰성 평가, 데이터 분석을 아우르는 ISC의 Tech R&D 직무가 이러한 관심을 발휘할 수 있는 곳이라 판단했습니다.

두 번째, 신소재공학을 전공하며 소재의 특성이 제품의 성능과 신뢰성을 좌우한다는 점을 학습했습니다. 아크릴 가공 현장에서는 에어컨 송풍과 같은 사소한 환경 변수가 불량으로 이어지는 것을 직접 확인했고, 원인을 규명해 공정을 개선하는 일에 관심을 갖게 되었습니다.

(이러한 이유로 지원하게 되었습니다.)

판단한 이유는 두 번째와 같습니다. (원래 ~ 이러한 이유로 지원했습니다. 라고 나오는게 좋은데 첫 번째가 판단이라 끝나서 첫 번째 문장을 수정하든 판단 이유가 들어가야 함)

입사 후에는 선배님들께 시제품 제작과 평가 방법을 배우고, 시험 데이터를 분석해 설계에 반영하는 엔지니어로 성장하겠습니다. 이후 신규 Concept 구조 개발에 참여하며 제품 신뢰성을 높이는 R&D 인력이 되겠습니다.
```

운영자가 직접 짚은 점: 첫 번째 이유가 "판단했습니다"로 끝나 판단한 이유가 빠져 있다. 그 이유는 두 번째 내용이다.

## 업그레이드 본 (위 샘플을 기준으로 다듬음)

```
제가 ISC Tech R&D에 지원한 이유는 두 가지입니다.

첫째, 소재와 작은 공정 조건이 제품의 신뢰성을 가른다는 것을 전공과 현장에서 직접 확인했기 때문입니다. 신소재공학을 전공하며 소재의 특성이 제품의 성능과 신뢰성을 좌우한다는 점을 학습했습니다. 아크릴 가공 현장에서는 에어컨 송풍과 같은 사소한 환경 변수가 불량으로 이어지는 것을 직접 확인했고, 원인을 규명해 공정을 개선하는 일에 관심을 갖게 되었습니다.

둘째, 테스트 소켓 분야에서 신규 구조 개발, 신뢰성 평가, 데이터 분석을 아우르는 ISC의 Tech R&D 직무가 이러한 관심을 실제 제품의 신뢰성으로 이어 갈 수 있는 곳이기 때문입니다.

이러한 이유로 ISC Tech R&D에 지원하게 되었습니다.

입사 후에는 선배님들께 시제품 제작과 평가 방법을 배우고, 시험 데이터를 분석해 설계에 반영하는 엔지니어로 성장하겠습니다. 이후 신규 Concept 구조 개발에 참여하며 제품 신뢰성을 높이는 R&D 인력이 되겠습니다.
```

샘플에서 바꾼 점:

1. 순서: 관심이 생긴 근거(전공·현장)를 첫째로, 그 관심을 펼칠 곳(ISC 직무)을 둘째로. 샘플은 첫째에 "이러한 관심"이 먼저 나와 무슨 관심인지 모른 채 읽게 된다.
2. 각 이유를 "~때문입니다"로 끝내 판단의 근거를 담았다. 첫째의 한 줄 요약 문장을 앞에 세워 이유가 먼저 보이게 했다.
3. 원문 문장(1차 "좋은 표현" 두 문장, "신규 Concept", "선배님들께")은 글자 그대로 옮겼다. 바뀐 것은 요약 문장 1개와 둘째의 끝맺음뿐이다.
4. 결론으로 닫는 문장("이러한 이유로 ISC Tech R&D에 지원하게 되었습니다.")을 넣었다. 운영자 샘플의 괄호 문장이자 상담 노트의 "결론으로 닫는다"이다.
5. 확인 필요는 그대로 따라간다: 둘째의 세부 업무(신규 구조 개발·신뢰성 평가·데이터 분석)는 실제 공고 문구로 확인 후 사용.

## 같은 문항의 다른 두괄식 스타일 (추천안용)

번호 없이 한 문장으로 이유를 먼저 말하는 첫 문장:

```
소재와 작은 공정 조건이 제품의 신뢰성을 가른다는 것을 전공과 현장에서 직접 확인했고, 그 원인을 찾아 개선하는 일을 테스트 소켓 분야의 ISC Tech R&D에서 이어 가고 싶어 지원했습니다.
```

이 문장으로 시작하면 "첫째·둘째"와 닫는 문장 없이 원문 문장을 그대로 이어 쓴다.

## 검토 체크리스트

- [ ] 첫 문장에 답(지원 이유의 개수 또는 핵심)이 있는가
- [ ] 결론으로 닫았는가(번호형일 때)
- [ ] 각 이유가 근거를 담고 "때문입니다"로 끝나는가 (근거 없는 "판단했습니다" 없음)
- [ ] "이러한/이 관심"이 가리키는 내용이 앞에 이미 나왔는가
- [ ] 원문 문장·숫자·영문 용어·고유명사·고객 말투가 그대로인가, 1차 "좋은 표현"은 글자 그대로인가
- [ ] 원문에 없는 이유를 만들지 않았는가, 이유가 하나면 하나로 썼는가
- [ ] 1차의 확인 필요 표시를 확인된 것처럼 바꾸지 않았는가

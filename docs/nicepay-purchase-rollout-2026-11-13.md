# NICE purchase rollout — 2026-11-13

The existing login, delivery preference, research consent, free credits, Play billing and Polar checkout remain active. The web handoff obtains authenticated payment capabilities and offers NICE card/easy payment choices. EASY opens the native NICE agreement/selection screen; it does not skip the merchant agreements or promise Toss support.

The server reads the buyer's payable run, calculates the canonical quote, and persists an immutable private order with owner, run, product, amount and price-source version before opening NICE. Browser amounts are rejected. Existing approved QUICK/PRO/FINAL and extra-block prices are unchanged. The stored quote and original billing amount remain the refund basis after future price changes. A runtime administrator price editor is a separate outstanding task; this release does not claim to provide one.

NICE authentication alone grants nothing. The return endpoint verifies signature, amount, merchant, order and TID, claims approval once, and verifies the server approval response. The database commits the paid ledger and entitlement together. The existing checkout-return component then starts the existing analysis endpoint automatically. Repeated callbacks do not approve twice. Unknown outcomes use network cancellation or delayed TID inquiry, never replay the approval. A competing purchase is recorded for cancellation and receives no second entitlement.

Analysis failure/timeout keeps the existing shared refund claim, dispatches cancellation by provider and refunds the stored original amount. An uncertain cancellation remains marked for operator review. No background webhook or scheduled NICE reconciliation is claimed: recovery currently runs when the authenticated checkout status is revisited. The provider query and cancellation endpoints are fixed official HTTPS addresses.

Rollout controls are server-only Worker Secrets: NICEPAY_ENABLED, NICEPAY_PUBLIC_ENABLED, NICEPAY_PILOT_USER_IDS, NICEPAY_MID and NICEPAY_MERCHANT_KEY. Keep public disabled until the approved real-payment/delivery verification. Pilot purchases carry testPurchase=true, are excluded from actual revenue and do not settle referral rewards. Keys never enter client bundles or tracked files. Review-only credentials/routes remain separate and cannot approve purchases.

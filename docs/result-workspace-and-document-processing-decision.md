# MOOA Resume 결과 워크스페이스 및 문서 처리 결정

작성일: 2026-08-16

## 결정 요약

MOOA Resume의 기준 결과물은 원본 파일을 자동으로 덮어쓴 HWP/PDF가 아니라 웹 결과 워크스페이스다.

원본 파일의 양식을 유지한 채 특정 문장만 정확한 위치에 삽입하는 기능은 파일 형식별 편집 엔진, 폰트, 표, 개체, 페이지 나눔, 보호 설정 등에 따라 결과가 달라진다. MVP에서 이를 핵심 기능으로 삼으면 정확성과 안정성이 떨어진다.

따라서 다음 원칙을 적용한다.

1. 업로드한 원본 파일과 추출 텍스트를 별도로 유지한다.
2. AI는 추출·정규화된 텍스트를 분석한다.
3. 결과는 문항별 첨삭 전/후, 수정 이유, 글자 수, 확인 필요 정보로 제공한다.
4. 사용자는 웹에서 수정하고 문항별 또는 전체를 복사한다.
5. 최종 제출본 화면에서는 비교 표시를 제거하고 제출할 문장만 제공한다.
6. DOCX, PDF, HWPX는 웹 기준본에서 생성하는 내보내기 기능으로 단계적으로 추가한다.
7. 기존 HWP/PDF 원본 양식을 자동으로 수정해 반환하는 기능은 MVP 범위에서 제외한다.

## 첨부파일 처리

현재 구현은 PDF, DOCX, TXT, MD 파일에서 브라우저가 텍스트를 추출해 입력창에 복원한다. 최대 크기는 10MB다. 원본 파일 자체는 서버에 저장하지 않는다.

향후 첨부 모델은 다음 데이터를 분리한다.

- 원본 파일과 파일명, 형식, 크기
- 추출한 원문
- 문항, 문단, 페이지 등 문서 구조
- 사용자가 추출 후 수정한 작업용 텍스트
- 분석에 사용한 불변 DocumentVersion과 SubmissionSnapshot

결제 전 게스트 단계에서는 서버 업로드와 외부 API 호출을 하지 않는다. 브라우저에서 읽을 수 있는 형식만 로컬 처리한다. 로그인과 상품 선택 이후에만 비공개 저장소로 원본을 전송하고 정밀 파싱을 수행한다.

## HWP와 HWPX

- HWPX는 ZIP/XML 기반이므로 구조 추출과 결과 생성 지원을 우선 검토한다.
- 레거시 HWP는 바이너리 형식과 호환성 문제 때문에 서버 전용 파서 또는 정식 변환 수단이 필요하다.
- HWP 파싱 실패 시 PDF, DOCX 또는 HWPX 변환을 안내한다.
- 실제 HWP 결과 파일을 제공하기 전 한컴오피스 호환성, 표와 글상자, 글꼴, 페이지 나눔을 별도로 검증한다.

## Upstage 사용 범위

Upstage Document OCR/Parse는 결과 문장을 생성하는 주 모델로 사용하지 않는다. 문서를 읽는 전처리 어댑터로 제한한다.

사용 후보:

- 스캔 PDF
- JPG, PNG 등 이미지 문서
- 텍스트 레이어가 없거나 깨진 PDF
- 표, 체크박스, 복잡한 레이아웃 보존이 필요한 문서
- 로컬 파서가 실패하거나 추출 품질이 낮은 문서

사용하지 않는 기본 경로:

- TXT, MD
- 정상적인 DOCX
- 텍스트 레이어가 정상인 PDF
- 로컬에서 안정적으로 읽을 수 있는 HWPX

처리 순서는 로컬 추출, 추출 품질 검사, 필요 시 결제 이후 서버에서 Upstage 호출이다. Upstage 결과는 원문과 페이지 위치를 함께 보존하고, 첨삭 모델이 만든 사실처럼 취급하지 않는다.

## 결과 화면

결과 화면은 다음 순서로 제공한다.

1. 가상 샘플 또는 실제 분석 여부 표시
2. 분석한 원본 첨부 카드
3. 가장 중요한 개선점 최대 3개
4. 문항별 첨삭 전/후 비교
5. 수정 이유와 확인이 필요한 사실
6. 사용자가 직접 수정 가능한 첨삭 후 문장
7. 문항별 복사와 전체 복사
8. 비교 표시가 없는 최종 제출본
9. TXT, DOCX, PDF, HWPX 내보내기

성과 수치나 경험을 생성하지 않는다. 확인할 수 없는 정보는 결과에 임의 반영하지 않고 확인 질문으로 남긴다.

## 이번 구현

- 결과 페이지를 문항별 결과 워크스페이스로 교체
- 첨삭 전/후 비교 제공
- 첨삭 후 문장 직접 수정
- 문항별 복사 및 전체 복사
- 최종 제출본 전환
- TXT 저장
- 원본 파일 참고 카드
- 고정 데이터가 실제 결과로 오해되지 않도록 가상 샘플 표시

DOCX, PDF, HWPX 생성과 실제 분석 데이터 연결은 다음 구현 단계로 남긴다.

## 2026-08-16 결과 경험 고도화

결과 화면을 타입 기반 작업공간 V2로 확장했다.

- ResultDocument Zod 스키마 추가
- 원본 첨부, 준비도 요약, 우선 개선점, 문항, 공고 요구 매칭, 확인 질문, 면접 질문을 하나의 버전 계약으로 정의
- 실제 AI 연결 전 검증할 수 있는 PRO fixture 분리
- 한눈에 보기, 문항별 첨삭, 공고·경험 분석, 면접 준비, 최종 제출본 탭 제공
- 문항은 읽기 모드가 기본이며 직접 수정을 선택한 경우에만 textarea 표시
- 사용자 수정본은 브라우저 세션에 자동 저장
- AI 수정본으로 되돌리기, 문항별 복사, 전체 복사, TXT 저장 제공
- 고정 점수와 지원서는 가상 샘플임을 반복 표시
- ResultDocument 스키마와 최종 문서 조합 함수 테스트 추가

첨부 UX도 다음과 같이 보완했다.

- 파일명, 확장자, 크기, 추출 완료 상태를 카드로 표시
- 추출된 텍스트를 수정해도 원본 첨부 표시 유지
- 첨부 제거와 추출 텍스트 삭제를 별도 행동으로 분리
- 파일 메타데이터를 게스트 세션에 저장해 온보딩까지 전달
- 미지원 형식에는 PDF·DOCX·TXT 변환 또는 직접 붙여넣기 대안 안내

현재 실제 지원 형식은 PDF, DOCX, TXT, MD이며 최대 10MB다. HWP/HWPX와 Upstage 연동은 실제 사용자 수요와 샘플 파일 검증 이후 진행한다.

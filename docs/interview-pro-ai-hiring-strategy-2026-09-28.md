## 1. 한 줄 결론

`기업 AI 채용전형 대비`를 면접 PRO의 부가 메뉴가 아니라 `일반·대면 면접 실전훈련`과 동급인 전면 축으로 만든다.

무아레쥬메가 자소서를 빼면 지원서 서비스의 설득력이 약해지는 것처럼, 앞으로의 면접 제품이 기업 주도 AI 전형을 다루지 않으면 사용자가 실제로 마주치는 채용 과정을 끝까지 책임진다고 말하기 어렵다.

다만 포지셔닝은 `AI 점수 공략`이나 `합격 알고리즘 해킹`이 아니다.

> 기업이 AI로 묻는 시대, 무아는 내 지원자료에서 나온 답변을 실제 전형 형식에 맞춰 말할 수 있게 훈련한다.

## 2. 왜 지금 전면에 둘 가치가 있는가

AI 채용전형은 먼 미래의 실험 기능이 아니라 기업이 이미 도입하고 형식을 계속 바꾸는 채용 단계다.

- 고용24가 소개한 2025년 채용담당자 조사에서는 응답 기업의 52.4%가 채용에 AI를 활용 중이거나 시범 도입 중이라고 답했다.
- JOBDA는 공식 FAQ에서 역량검사를 활용하는 기업이 800곳 이상이라고 안내한다.
- 글로벌 HireVue는 녹화형 평가뿐 아니라 지원자 답변에 따라 후속 질문을 만드는 대화형 AI Interviewer를 운영하고 있다.
- 고용노동부도 AI 채용 관련 가이드라인과 구직자용 AI 면접 공간을 운영하며 제도권 채용 방식으로 대응하고 있다.

여기서 중요한 점은 `AI 면접 = 화면에 AI 사람을 띄우는 기능`이 아니라는 것이다. 실제 제품 가치는 다음 세 가지에서 생긴다.

1. 기업이 정한 응시 형식과 시간 압박을 재현한다.
2. 지원자의 말이 질문·직무·지원자료와 일치하는지 평가한다.
3. 한 번의 체험이 아니라 부족한 부분을 다시 연습해 개선시킨다.

따라서 면접관 아바타의 화려함보다 `전형 포맷 대응 속도`, `지원자료 근거`, `꼬리질문 논리`, `반복 훈련`을 먼저 완성해야 한다.

## 3. 면접 PRO의 최종 구조

```text
면접 PRO
├─ 일반·대면 면접 실전훈련
│  ├─ 인성·직무·경험 면접
│  ├─ 지원자료 기반 예상질문
│  ├─ 검증형·압박형 꼬리질문
│  └─ 영상·음성 복기와 약점 재훈련
│
└─ 기업 AI 채용전형 대비
   ├─ 녹화형 영상면접
   ├─ 대화형 AI 면접
   ├─ 역량·상황·경험형 면접
   ├─ 기업/솔루션별 응시 형식 재현
   └─ 결과 분석과 재훈련
```

사용자가 어느 쪽인지 모를 때는 세 번째 진입점 `내 전형 확인하기`를 제공한다. 채용 안내문·이메일·문자·스크린샷을 넣으면 무아가 전형 형식을 정리하되, 불확실한 내용은 추측하지 않고 확인을 요청한다.

## 4. 제품 약속과 금지선

### 제품이 약속할 것

- 실제와 유사한 준비시간·답변시간·문항 흐름을 경험하게 한다.
- 자소서·이력서·공고·직무분석에서 질문과 답변 근거를 연결한다.
- 질문의 의도와 답변에서 확인된 근거, 빠진 근거를 설명한다.
- 같은 약점을 다시 말해 보고 이전 세션과 비교하게 한다.
- 외운 문장을 그대로 낭독하는 답변과 핵심을 자기 말로 재구성한 답변을 구분해 코칭한다.

### 제품이 약속하지 않을 것

- 특정 기업·솔루션의 비공개 평가 공식을 안다고 주장하지 않는다.
- 합격 확률, AI 통과 확률, 예상 서열을 만들지 않는다.
- 표정·외모·시선·성별·연령·억양을 역량이나 자신감 점수로 환산하지 않는다.
- 근거가 없는 기업별 기출·문항 수·제한시간을 사실처럼 보여주지 않는다.
- 게임형 역량검사를 초기 MVP에서 어설프게 복제하지 않는다.

## 5. 가장 중요한 제품 해자: AI 채용전형 포맷 레지스트리

기업 주도로 전형이 빠르게 바뀌면 하나의 고정된 `AI 면접 모드`만 만들어서는 곧 낡는다. 면접 PRO에는 기업·솔루션별 형식을 갈아 끼울 수 있는 `전형 포맷 레지스트리` 개념이 필요하다.

각 포맷은 최소한 다음 정보를 가진다.

- 기업명, 채용공고, 직무, 전형명
- 확인된 솔루션 또는 플랫폼명
- 녹화형 / 대화형 / 역량형 구분
- 질문당 준비시간과 답변시간
- 예상 문항 수와 전체 소요시간
- 다시 녹화 가능 여부
- 텍스트·음성·영상 입력 방식
- 장비·브라우저·환경 조건
- 확인 출처와 마지막 확인일
- `공식 확인 / 사용자 제보 / 미확인` 신뢰 상태

초기에는 별도 공개 DB나 테이블을 먼저 만들지 않는다. 기존 면접 세션의 `mode/settings/snapshot` 경계 안에서 검증하고, 실제로 여러 포맷을 반복 운영할 필요가 확인될 때 영속 구조를 도입한다.

### 포맷 수집 원칙

1. 기업 채용공고·공식 안내와 솔루션 공식 문서를 우선한다.
2. 사용자가 올린 초대 화면은 해당 지원 건에서만 비공개로 사용한다.
3. 사용자 제보는 다른 사용자에게 곧바로 사실로 노출하지 않는다.
4. 형식이 바뀌면 이전 정보를 덮어쓰기보다 확인일과 버전을 남긴다.
5. 특정 경쟁사 화면·캐릭터·문항을 그대로 복제하지 않는다.

이 레지스트리가 있으면 `기업이 새 전형을 도입 → 무아가 형식을 확인 → 연습 시나리오를 빠르게 추가`하는 대응 체계가 생긴다. 단순 AI 면접 체험보다 장기적으로 더 강한 자산이다.

## 6. AI 채용전형 대비의 세 가지 훈련 모드

### A. 녹화형 영상면접

- 질문 확인
- 준비시간 카운트다운
- 제한시간 녹화
- 재녹화 허용/불가 시나리오
- 문항 사이 자동 전환
- 세션 종료 후 일괄 피드백

화면은 사람 면접관 연출보다 `기업 시험 화면`에 가깝게 만든다. 실전 중에는 코칭 문구를 숨기고 타이머·녹화 상태·문항만 분명히 보여준다.

### B. 대화형 AI 면접

- 첫 답변의 누락·모호함·사실 확인 필요 지점을 찾는다.
- 앞선 답변을 근거로 후속 질문을 생성한다.
- 동일 질문을 반복하지 않고 대화 흐름을 유지한다.
- 후속 질문이 왜 나왔는지 세션 종료 후 공개한다.

### C. 역량·상황·경험형 면접

- 행동사례, 갈등, 문제해결, 협업, 책임, 실패, 학습 질문을 다룬다.
- STAR를 형식적으로 채웠는지가 아니라 실제 행동과 결과가 구체적인지 본다.
- 지원자료에 없는 수치·성과·역할은 생성하지 않고 확인 필요로 표시한다.

게임형 역량검사는 별도 도메인으로 보고 후순위로 둔다. 영상·음성 면접의 품질을 입증하기 전에는 포함하지 않는다.

## 7. 연습모드와 실전모드

### 연습모드

- 질문 의도 표시
- 답변에 필요한 핵심 근거와 키워드 표시
- 말하기 전 구조 힌트 제공
- 답변 직후 짧은 코칭
- 같은 질문 즉시 재시도 가능

### 실전모드

- 힌트와 예시 답변 숨김
- 실제 포맷의 준비·답변시간 적용
- 한 번만 재생되는 질문 옵션
- 문항 중간 피드백 금지
- 세션이 끝난 뒤 전체 결과 공개

두 모드는 같은 평가 기준을 사용하되 사용자 경험을 분리한다. 연습모드에서 배운 문장을 실전모드에서 그대로 읽게 하는 것이 아니라, 키워드만으로 자신의 말로 복원하도록 단계적으로 힌트를 줄인다.

## 8. 설명 가능한 평가 체계

모든 정성 평가는 점수만 주지 않고 해당 발화 구간과 이유를 함께 보여준다.

### 답변 내용

- 질문 적합성: 실제로 물은 것에 답했는가
- 핵심 메시지: 가장 중요한 결론이 초반에 드러나는가
- 구체적 근거: 행동·상황·결과가 확인 가능한가
- 직무 관련성: 공고의 역할·요건과 연결되는가
- 구조: 맥락에서 행동과 결과까지 자연스럽게 이어지는가
- 주도성: 본인의 기여와 팀의 기여가 구분되는가
- 성찰: 실패·갈등 이후 무엇을 배웠는가
- 일관성: 이력서·자소서·이전 답변과 충돌하지 않는가
- 사실 안전성: 새로 만들어 낸 수치·성과·경력이 없는가

### 말하기 전달

- 전체 길이와 제한시간 준수
- 말하기 속도와 긴 침묵
- 불필요한 반복과 군더더기
- 결론까지 걸린 시간
- 문장 미완성과 습관어
- 녹음 품질과 음량 안정성

말하기 전달 지표는 `잘생겨 보이는가`, `자신감 있어 보이는가` 같은 인상 평가가 아니라 사용자가 직접 고칠 수 있는 관찰값으로 제한한다.

## 9. 무아만의 대표 기능

### 9.1 질문 의도 카드

답변 전에 `이 질문은 무엇을 확인하려는가`를 한 문장으로 보여준다. 실전모드에서는 숨기고 종료 후 복기에서 공개한다.

### 9.2 AI 면접관 노트

각 답변에 대해 다음을 기록한다.

- 확인된 사실과 역량
- 아직 확인하지 못한 핵심
- 지원자료와 충돌하거나 불명확한 부분
- 다음 질문으로 검증해야 할 부분

### 9.3 꼬리질문 생성 이유

`왜 이 질문이 나왔는지`를 사용자가 이해해야 반복 훈련이 가능하다.

예시:

```text
답변에서 “프로세스를 개선했다”고 말했지만
본인의 구체적인 행동과 개선 결과가 나오지 않아 확인 질문을 만들었습니다.
```

### 9.4 면접 흐름 그래프

```text
지원동기
  └─ 직무 이해 확인
       └─ 실제 경험 근거 부족
            ├─ 역할 확인 질문
            └─ 결과 수치 확인 질문
```

사용자는 단순 문답 목록이 아니라 어느 답변 때문에 질문이 깊어졌는지 볼 수 있다.

### 9.5 꼬리질문 강도

- 기본: 빠진 내용을 보충
- 검증: 사실·역할·결과의 일관성을 확인
- 압박: 반론·실패·우선순위 충돌에 대응

압박모드도 공격적 인격평가가 아니라 답변 논리와 근거를 검증하는 범위로 제한한다.

### 9.6 암기 답변 감지와 자연어 재표현 훈련

FINAL에서 만든 답변과 실제 발화를 비교해 `핵심은 유지했지만 자기 말로 표현함`, `문장 전체를 낭독하는 경향`, `핵심 근거가 빠짐`처럼 설명한다. 외운 티를 감정 점수로 추측하지 않고 텍스트 유사도·멈춤·문장 구조 같은 관찰 근거로 판단한다.


## 11. 기존 QUICK·PRO·FINAL과 연결

면접 PRO는 독립 구매가 가능하지만 기존 상품을 사용한 사람에게는 자료를 다시 입력하게 하지 않는다.

```text
직접 진입 ─┐
QUICK ─────┤
PRO ───────┼─> ApplicationCase 선택
FINAL ─────┘      └─> 최신 자료 확인
                       └─> 새 SubmissionSnapshot 고정
                            └─> 면접 PRO 세션 시작
```

- QUICK 사용자는 기본 자료를 가져오고 면접 전 확인할 부족 정보부터 보완한다.
- PRO 사용자는 예상질문·리스크·직무분석을 가져온다.
- FINAL 사용자는 30초·1분 자기소개, 답변팩, 키워드, 근거를 그대로 이어 쓴다.
- 면접 PRO 단독 사용자는 이력서·자소서·공고를 새로 넣고 면접에 필요한 최소 분석만 수행한다.

각 세션은 시작 당시의 문서 버전을 `SubmissionSnapshot`으로 고정한다. 이후 문서가 바뀌어도 과거 세션의 질문·답변·피드백 근거가 뒤틀리지 않아야 한다.

## 12. 경쟁 제품과의 차별화

### JOBDA

강점은 많은 기업이 실제로 사용하는 역량검사 생태계와 게임·질문·응시 경험이다. 무아는 그 검사를 복제하기보다 사용자의 특정 지원 건과 답변 근거를 중심으로 준비시킨다.

### 에듀스 inFACE

AI휴먼, 텍스트·대화형 면접, 직무·기업·자소서 기반 질문, 연습과 실전 평가 등 면접 형식의 범위가 넓다. 무아는 화려한 면접관 연출보다 문서 버전과 문단 근거, 답변 충돌 확인, 꼬리질문 이유, 약점 재훈련을 더 깊게 가져간다.

### 사람인 AI 모의면접

공고·이력서 기반 질문, 동적 꼬리질문, 여러 AI휴먼, 리포트와 가격 접근성이 강하다. 무아가 단순 질문 생성과 AI 사람 수로 경쟁하면 불리하다. `지원자료 작성부터 면접 발화까지 이어지는 하나의 증거 체인`과 세션 전후 개선을 전면에 둔다.

### HireVue 등 기업용 솔루션

HireVue는 공식 설명에서 영상 자체나 음성의 톤을 평가하지 않고 답변을 전사한 텍스트의 의미를 직무 역량 기준으로 평가한다고 밝힌다. 따라서 준비 서비스도 표정 점수 놀이보다 질문 적합성·구체적 근거·직무 연관성·답변 일관성을 우선해야 한다.

## 13. AI 면접관 사람 형상은 핵심이 아니다

초기 버전에서 실시간 사람형 아바타는 만들지 않는다.

시장 전체의 방식별 점유율 통계가 없어 `대부분`이라고 수치로 단정하지는 않는다. 그러나 HireVue의 일방향 비동기 영상면접과 JOBDA 공식 응시 흐름처럼 대표적인 기업용 영상면접은 사람형 아바타보다 `사전 질문 → 준비시간 → 지원자 카메라 녹화 → 제한시간 답변 → 제출` 구조를 사용한다. 실제 전형 재현이라는 목적에는 이 시험형 UI가 더 가깝다.

- 일반면접 루트: 정적 면접관 이미지 또는 간단한 사전 제작 영상 + 자연스러운 TTS
- AI 채용전형 루트: 질문 카드 + 준비시간 + 카메라·마이크 녹화 + 답변시간 + 자동 전환
- 대화형 AI 전형: 음성 질문과 동적 꼬리질문을 사용하되 사람 얼굴은 선택사항
- 사용자 반응 검증 후: 직무·압박 강도가 다른 면접관 페르소나
- 충분한 효과와 지불의사 확인 후: HeyGen LiveAvatar, Tavus CVI, D-ID 같은 실시간 아바타 PoC

실시간 아바타는 지연시간·비용·모바일 성능·불쾌한 골짜기·장애 대응 부담이 크다. 경쟁사가 AI 사람을 보여준다고 해서 그것부터 따라가는 것은 제품의 본질과 다르다. 같은 개발비라면 포맷 프리셋, 녹화 안정성, 실패 복구, 답변 분석의 설명 가능성에 먼저 투자한다.

## 14. 1차 MVP 범위

### 반드시 포함

- 일반면접 / 기업 AI 채용전형 두 개의 최상위 진입
- 녹화형과 대화형 AI 면접
- 준비·답변시간 설정
- 카메라·마이크 녹화와 STT
- 질문 TTS
- 지원자료 기반 질문과 사실 충돌 확인
- 설명 가능한 내용·말하기 피드백
- 꼬리질문 이유와 면접관 노트
- 약점 문항 재연습
- 세션 이력과 전후 비교
- 녹화물 보존·삭제 정책과 사용자 제어

### 이후 검증

- 여러 면접관 페르소나
- 기업/솔루션 포맷 자동 추천 확대
- 실시간 대화 최적화
- 실시간 아바타
- 게임형 역량검사

### 만들지 않음

- 합격 확률
- 얼굴·시선·감정·외모 점수
- 비공개 기업 알고리즘 모사 주장
- 녹화물의 무기한 기본 보관

## 15. 개발 순서

1. 기존 텍스트 모의면접의 질문 신뢰·턴 예약·중복 호출 문제를 먼저 보완한다.
2. 면접 세션에 일반/AI 채용전형 모드와 시간 설정을 추가한다.
3. 마이크 녹음 → STT → 기존 평가 파이프라인을 연결한다.
4. 질문 TTS와 실전 카운트다운을 추가한다.
5. 카메라 셀프뷰와 로컬/단기 보존 녹화 복기를 추가한다.
6. 녹화형 AI 전형의 일괄 피드백을 완성한다.
7. 대화형 꼬리질문과 생성 이유를 완성한다.
8. 포맷 레지스트리를 소수의 공식 확인 포맷으로 운영 검증한다.
9. 세션 비교와 약점 재훈련을 묶어 유료 프로그램 가치를 검증한다.
10. 아바타·게임형 검사는 이후 별도 의사결정한다.

## 16. 성공 지표

합격률이나 AI 통과확률 대신 제품이 실제로 개선할 수 있는 지표를 본다.

- 첫 세션 완주율
- 약점 질문 재연습률
- 두 번째 세션에서의 질문 적합성·근거 구체성 개선
- 제한시간 초과 감소
- 사실 충돌·검증 필요 항목 해결률
- FINAL 답변팩에서 면접 PRO로 이어진 비율
- 독립 면접 PRO 사용자의 자료 입력 완료율
- 사용자 스스로 `실제 전형과 유사했다`고 평가한 비율

## 17. 가격과 상품 표현

면접 PRO 단독 가격의 초기 기준은 사용자가 결정한 `59,000원`을 유지한다. 다만 59,000원은 단순 AI 면접 1~3회 응시권으로 설명하면 비싸다.

판매 단위는 다음과 같이 표현해야 한다.

> 한 지원 건의 전형 확인 → 답변 준비 → 일반/AI 실전연습 → 복기 → 약점 재훈련 → 이전 세션 비교까지 끝내는 면접 완성 프로그램

정확한 포함 세션 수·음성 분량·영상 보관 기간·추가 이용권 가격은 구현 후 실제 STT/TTS/모델/저장·전송 비용을 측정해 결정한다. QUICK·PRO·FINAL 구매자의 전환 가격도 이 측정 전에는 확정하지 않는다.

## 18. 최종 제품 판단

기업 AI 채용전형 대비는 충분히 강한 메리트가 있다. 그러나 경쟁력은 `우리도 AI 면접관이 있다`에서 나오지 않는다.

무아레쥬메가 가져가야 할 독자성은 다음 조합이다.

```text
기업 전형 형식의 빠른 반영
+ 지원자료 원문 근거
+ 사실 충돌 방지
+ 설명 가능한 꼬리질문
+ 암기에서 실제 발화로 이어지는 훈련
+ 세션별 개선 기록
```

이 조합이면 자소서 첨삭 서비스의 부가 기능이 아니라, `지원서에서 실제 면접까지 이어지는 취업 전용 운영체제`로 제품을 확장할 수 있다.

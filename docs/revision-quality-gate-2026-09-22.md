# 반복 첨삭 품질 게이트 — 2026-09-22

대상: QUICK·PRO·FINAL / POLISH·BUILD·CREATE. 기존 사실성 검증 뒤 별도 모델 요청으로 원문과 수정안을 같은 다섯 기준으로 평가한다. 반복 횟수 보너스, 강제 점수 하한, 첨삭본 자동 합격은 없다.

## 채택과 유지

모든 평가 항목에서 악화가 없고, 실제 원문·후보 인용으로 개선이 확인되고, 새 오류·사실/개성 손실·해결한 문제의 재등장·취향상 교체가 없어야 수정안을 채택한다. 전체 문서를 채택하거나 전체 원문을 유지한다. 문항별로 섞으면 평가자가 검토하지 않은 새 문서가 되므로 혼합하지 않는다.

CREATE/BUILD에서 원문이 빈 문항의 후보가 거절되면 빈 글을 완료로 전달하지 않고 기존 실패·재시도 흐름을 따른다. 원문 유지에서도 실제 남은 지적은 숨기지 않는다. FINAL에서 수정안이 거절되면 '제거/완화 완료' 표시를 '지원자 확인 필요'로 바꾼다.

priorities 0~3, 수정 이유 0~5, consultingAdvice 0~8을 허용한다. 준비도 판단 근거는 하나 이상 유지한다(강점도 근거 가능). 실제 문제 개수·원문 유지 상태를 주 결과 화면에 표시하며 빈 사실확인 상자와 유지 결과에 대한 분량 채우기 재구매 유도를 숨긴다.

## 이전 결과 확인

같은 소유자의 현재 실행보다 먼저 완료된 결과 중, SHA-256 맥락 지문이 동일한 최근 20개만 조회한다. 맥락은 상품·작성 단계·스타일·첨삭 방향·회사/직무·문항/목표 길이·다른 자료와 요청사항을 포함한다. 답변은 NFC와 공백 정규화 후 정확히 비교한다. 외부 요청에 붙인 이전 결과 주장은 입력 스키마가 제거한다.

`revisionQuality`에 평가 버전·평가 응답/모델·전후 점수·채택 판정/이유·입력과 맥락 지문·부모 실행을 저장한다. 기존 결과는 계속 읽히지만 맥락 지문 없는 과거 결과를 동일 조건의 평가로 추정하지는 않는다. 새 DB 표나 migration은 없다.

동일 입력의 핵심 지적 종류/심각도 변경, 5점 초과 상승, 근거 없는 점수 하락은 보류한다. 실제 오류를 현재 원문에서 인용하면 기존 판단 정정과 점수 하락도 가능하다. 이전 B를 정확히 A로 되돌리는 경우도 오류 인용을 요구한다. 의미가 비슷한 다른 표현으로의 회귀는 평가 모델 판단에 의존한다.

## 실행·비용·복구

브라우저와 cron은 공용 2단계 실행기를 쓴다. 실행 중 response_id에 `quality-v1|writerId|reviewerId`를 저장하고 완료 시 실제 작성 응답 ID로 돌아간다. 비교 후 갱신(CAS)과 60초 시작 lease로 정상 동시 조회의 중복 재평가 요청을 막고 중단 후 재개한다. 공급자가 수락한 뒤 네트워크 응답을 잃으면 고아 호출이 생길 수 있어 과금의 exactly-once는 보장하지 않는다.

작성+재평가 토큰을 합산하고 사용량 불명은 null로 둔다. 추가 모델 호출 한 번으로 처리시간과 원가가 늘어난다. 기존 가격·이용권·모델 선택·10분 전체 제한은 바꾸지 않았다. 실패/불완전/형식 오류/설명 없는 평가 변경은 재시도·실패 경로로 보내며 검토 안 된 후보를 전달하지 않는다.

PRO/FINAL 부가 분석 필드는 보존한다. 독립 검토는 핵심 진단과 수정본 품질을 확인하며, 모든 면접 항목을 별도로 다시 생성하는 것은 아니다.

개발 브랜치 보존 기준은 `a3e8d2b2b860344c5f78359941d04d7b1a621e7f`, 실제 배포의 main 기준은 `89e8b9810758d9c0426c35b21a0fa029e0490b99`다. 이전 운영 Worker는 `9ae15494-64d8-4303-90d8-66b4cd31c2c2`. 이전 worker는 새 실행 중 커서를 이해하지 못하므로 `quality-v1|...` 진행 건을 먼저 끝내거나 커서 대응 복구 후 롤백한다. 완료된 결과는 하위 호환이다.

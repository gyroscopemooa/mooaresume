# 면접 PRO — 답변 피드백·음성 전사 연결

기준일: 2026-09-28. 범위: 로컬 개발자/관리자 테스트. 운영 출시·배포 문서가 아니다.

## 이번 변경의 핵심

면접 결과의 중심을 **답변의 문제 → 원문 근거 → 왜 문제인지 → 수정 초안 → 재연습**으로 둔다. 파형·음량·음높이·영상 기준점은 원본을 확인하는 보조 근거이며, 그 숫자 자체가 면접 점수는 아니다.

실제 OpenAI API를 호출할 수 있는 서버 코드와 UI 연결을 구현했다. 다만 이번 개발 검증에서는 비용이 발생하는 전사/분석 요청을 실행하지 않았다. 따라서 **연결 코드·입력/출력 계약·권한·오류 처리 검증 완료**와 **실제 계정의 모델 권한·실제 면접 답변 품질 검증 완료**를 구별해야 한다.

## 현재 사용 흐름

1. `http://127.0.0.1:3000/dev/interview-pro-v2/studio` 또는 면접 결과 화면으로 이동한다.
2. 같은 호스트의 `http://127.0.0.1:3000/MAIL`에서 기존 관리자 인증을 완료한다. `localhost`와 `127.0.0.1`의 브라우저 쿠키는 별개다.
3. 직접 작성한 답변을 입력하거나, 본인이 선택한 녹화/음성에서 음성을 추출한다.
4. 음성 전사 사용 시 외부 AI 전송 동의 후 전사를 요청한다. 영상 컨테이너는 전송하지 않는다.
5. 전사문을 원본과 대조하고 잘못 인식한 내용을 수정한다. 직접 입력한 답변도 내용 확인이 필요하다.
6. 기업·직무·질문·확인한 답변을 명시적 동의와 함께 분석 요청한다.
7. 강점, 개선 우선순위 최대 3개, STAR 근거, 수정 초안, 추가 확인 질문, 예상 꼬리질문을 확인한다. 원음/계측은 필요할 때 펼쳐 확인한다.

마이크가 없는 사용자는 텍스트만으로 답변 내용 피드백을 받을 수 있다. 음성/영상이 없다는 이유로 해당 영역을 0점 처리하지 않는다. 전사문 확인을 하지 않으면 서버가 피드백 요청을 거절한다.

## 모델과 서버 설정

```dotenv
INTERVIEW_PRO_AI_ENABLED=true
OPENAI_MODEL_INTERVIEW_PRO=gpt-6-astra
OPENAI_MODEL_INTERVIEW_TRANSCRIBE=whisper-1
```

기존 `OPENAI_API_KEY`와 `MAIL_ADMIN_SECRET`를 서버에서 사용한다. 키/관리자 비밀번호를 클라이언트 응답이나 문서에 기록하지 않는다. 설정을 바꾼 뒤에는 개발 서버 재시작 또는 Next의 환경변수 재로딩 상태를 확인한다.

- 피드백 모델 기본값은 `gpt-6-astra`. 기존 자소서의 `OPENAI_MODEL`이나 `OPENAI_MODEL_FINAL`로 조용히 대체하지 않는다.
- 현재 피드백 호출은 `reasoning.effort=medium`, 출력 상한 6,000토큰이다. 사용자가 개발 에이전트의 추론 수준을 높이는 것과 서비스 API의 추론 수준은 서로 다른 설정이다.
- 전사는 `whisper-1`의 `verbose_json`과 세그먼트 타임스탬프를 사용한다. 현재 어댑터는 이 모델만 허용한다. 다른 전사 모델을 쓰려면 응답/타임스탬프 계약부터 별도로 구현·검증해야 한다.
- Astra에는 확인된 전사/텍스트를 보낸다. 이번 답변 API가 원음·영상을 직접 이해한다고 설명하지 않는다.
- `INTERVIEW_PRO_AI_ENABLED`가 정확히 `true`가 아니면 유료 호출 경로는 비활성이다.

이 날짜의 로컬 설정은 root 에이전트가 위 3개 값을 반영했다. 관리자 인증을 포함한 상태 조회에서 `authorized/configured/enabled=true`와 HTTP 200을 확인했다. 이는 키 존재와 로컬 설정/권한 확인이며, 제공자 측 모델 접근 권한이나 결제 상태 확인 호출은 아니다.

공식 근거: [Astra 모델 및 지원 입출력](https://developers.openai.com/api/docs/models/gpt-6-astra), [파일 음성 전사·타임스탬프](https://developers.openai.com/api/docs/guides/speech-to-text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## API 계약

| 경로 | 입력 | 반환 / 주요 경계 |
|---|---|---|
| `GET /api/dev/interview-pro/status` | 로컬 요청, 선택적으로 관리자 쿠키 | 설정/인증/활성화 여부, 모델명, 제한, 안내. 비인증 응답에는 실제 설정/모델명을 노출하지 않음 |
| `POST /api/dev/interview-pro/transcribe` | multipart: `file`, `consent="true"`, UUID `requestId` | `text`, `segments[{start,end,text}]`, 검증한 WAV 길이, 모델/스키마/요청 메타데이터 |
| `POST /api/dev/interview-pro/feedback` | JSON: UUID `requestId`, `consent=true`, `transcriptConfirmed=true`, `question`, `company`, `role`, `answerText`, `durationSeconds`, `transcriptSource` | `feedback`와 `metadata`. 타입은 공유 Zod 계약으로 검증 |

공유 계약은 `src/domain/interview-feedback.ts`에 있다. 프런트엔드도 응답 스키마를 사용하며 임의 형변환만으로 결과를 신뢰하지 않는다.

피드백 결과:

- 전체 요약과 강점 최대 3개: 제목, 원문 인용, 이유.
- 개선 우선순위 최대 3개: 제목, 원문 인용, 이유, 해당 부분의 수정 초안, 구체적 연습.
- STAR: 상황·과제·행동·결과별 `present/partial/missing/not_applicable`, 근거, 설명. 모든 질문에 STAR를 억지로 강제하지 않는다.
- 전체 답변 수정 초안, 사실 추가 확인 질문, 예상 연습용 꼬리질문.
- 이번 입력으로 평가하지 않은 매체/항목 및 초안 사실 확인 안내.
- 메타데이터: 실제 응답 모델명, prompt/rubric/schema 버전, 제공자가 반환한 입력·출력·전체 토큰, response ID, request ID. 토큰이 없으면 0이 아닌 `null`.

현재 메타데이터는 응답에 포함되지만 DB의 `AnalysisRun`으로 영구 기록하지 않는다. 운영 실행 이력·원가 추적이 완성됐다는 뜻은 아니다.

## 접근 제어와 루프백 별칭

- `NODE_ENV=development`가 아니면 404. 운영 페이지가 존재하더라도 이 API를 운영에서 열지 않는다.
- 요청 URL, 실제 `Host`, 존재하는 `x-forwarded-host` 모두 `localhost`, `127.0.0.1`, `[::1]` 루프백 허용목록과 포트 검증을 통과해야 한다.
- Next 개발 서버가 `request.url`의 호스트를 `localhost`로 정규화할 수 있으므로 실제 브라우저가 `127.0.0.1`인 경우를 허용한다.
- POST `Origin`은 **실제 Host 기준 origin에 정확히 일치**해야 한다. forwarded 헤더를 근거로 다른 사이트의 Origin을 허용하지 않는다.
- POST는 기존 서버 측 `isAdminRequest` 인증이 필수다. 화면의 플래그를 신뢰하지 않는다.
- 응답은 `Cache-Control: no-store, private`. 오류에 제공자 원문, 파일명, 프롬프트, 키, 사용자 문서를 포함하지 않는다.

이는 로컬 개발의 다중 방어선이다. 인터넷 공개 운영에 사용할 사용자 인증·RLS·영구 사용량 제어를 대체하지 않는다. 휴대폰의 LAN 주소 접속 등 비루프백 테스트도 현재 AI API에서는 차단된다.

## 데이터 경계와 개인정보

| 처리 | 외부로 보내는 데이터 | 보관/제한 |
|---|---|---|
| 로컬 계측/영상 기준점 | 해당 기능 자체는 사용자 미디어를 전송하지 않음 | 기존 로컬 분석의 범위·한계 문서 참조 |
| 음성 전사 | 선택한 파일에서 추출한 음성 WAV | 원래 파일명 대신 `interview-audio.wav`. 사용자 동의 후 OpenAI 전사 API로 전송 |
| 답변 내용 피드백 | 기업·직무·질문·확인된 답변 텍스트·전사 출처 | OpenAI Responses에 `store:false`. 원본 영상·원음·관리자 초안 전체는 전송하지 않음 |
| 임시 중복 방지 | 서버 프로세스 내부 UUID/해시/임시 결과 | 결과·전사 원문 참조는 10분 후 능동 해제. UUID+SHA256 표시만 최대 1시간 후 삭제 |

서버는 신규 DB 테이블·스토리지 업로드·원문 파일 저장·원문 로그를 만들지 않는다. 브라우저 파일/결과를 새로고침이나 해제로 놓는 것과 서버 임시 결과의 TTL은 별도다.

`store:false`는 제공자 측 모든 로그·보존 정책을 없애거나 Zero Data Retention을 보장한다는 뜻이 아니다. 외부 AI에 텍스트/음성을 보낸다는 안내와 동의가 필요하다.

전사 업로드는 최대 12MB, 최대 180초다. MIME만 믿지 않고 RIFF/WAVE 서명·청크·PCM16·16kHz·모노·바이트 길이·실제 PCM 길이를 검사한다. 숨은 추가 청크, 영상 컨테이너, 잘못된 길이, 완전 무신호를 제공자 호출 전에 거부한다. 서버는 본문 스트림 자체에도 상한을 적용한다.

음성 파일은 취소 요청 시에도 네트워크/제공자에서 이미 처리되었을 수 있다. 취소가 무조건 미과금 또는 삭제 완료를 뜻하지 않는다.

## 내부 프롬프트와 기존 관리자 초안의 차이

현재 **실행 중인** 답변 분석은 `src/server/ai/interview-pro/feedback-gateway.ts`의 서버 전용 프롬프트다.

- prompt: `interview-feedback-2026-09-28.1`
- rubric: `interview-content-star-1.0`
- schema: `interview-feedback-1.0`
- STT schema: `interview-transcription-1.0`

회사 이름은 맥락으로만 사용한다. 비공개 회사 채점 기준·실제 기출·채용 결과를 안다고 주장하지 않는다. 답변 안의 지시문은 분석 자료로 취급하며 시스템 지시로 승격하지 않는다.

기존 `/dev/interview-pro-v2/analysis` 워크벤치의 프롬프트 편집, 사용자 철학을 담은 전체 수행 v2 기준, PDF/DOCX 기반 7영역 평가표, 배점 저장, 10개 평가 관점 기획은 **별도의 참고/설계 초안**이다.

- 워크벤치의 localStorage 초안이나 배점을 바꿔도 이 API의 서버 프롬프트가 바뀌지 않는다.
- PDF/DOCX의 평가표를 이 API가 매 호출 자동 읽거나 100점으로 채점하지 않는다.
- 지금 연결은 한 모델의 문항별 내용 코칭이며, 10명/10관점 독립 심사와 합의 엔진은 아니다.
- 전체 수행 초안의 입장·퇴장·예절·전신 행동 기준은 이 텍스트 API로 평가하지 않는다.
- 기존 관리자 초안에는 클라이언트로 전달되는 참고 정의가 있다. 관리자 화면 인증만으로 초안 전체를 영업비밀 보안 저장소처럼 설명하면 안 된다. 이번 실행 프롬프트는 `server-only` 경계를 갖지만, 출력에서 일부 기준을 유추할 가능성까지 차단하는 것은 아니다.

기획을 실제 엔진으로 승격할 때에는 서버에서 승인된 버전/평가 범위를 선택하고, 근거·예외·동일 데이터 평가 재현성·변경 이력을 테스트해야 한다. 브라우저 초안을 그대로 신뢰해 실행 프롬프트로 올리지 않는다.

## 근거 검증과 품질 한계

1. 모델 응답이 완료 상태인지, 거절인지, 지정한 JSON 계약을 만족하는지 확인한다. 실패하거나 불완전한 응답을 그럴듯한 결과로 대체하지 않는다.
2. 강점/개선 및 STAR의 원문 인용은 확인된 답변의 **연속 부분 문자열**이어야 한다. `present/partial` STAR에 인용이 없으면 거부한다.
3. 수정 답변에 원문에 없는 아라비아 숫자/수치 표현이 새로 등장하면 거부한다.
4. 없는 경험·행동·성과를 만들지 않도록 지시하고, 필요한 사실은 대괄호 확인 항목과 질문으로 남긴다.
5. **2~3번이 모든 서술적 사실의 진실성을 보증하지는 않는다.** 같은 숫자를 잘못된 맥락에 쓰는 경우, 원문에 없는 비수치 성과·역할 등을 완벽하게 기계 검출하는 엔진은 아니다. 최종 수정안은 사실 확인이 필요한 연습 초안이다.
6. STT의 빈 결과, 역순/겹침/길이 초과 타임스탬프를 거부한다. 정상 스키마의 전사도 오인식·생략 가능성이 있으므로 사용자 확인을 필수로 받는다.
7. 전사문 공백 단위 수·눈에 보이는 필러를 세는 순수 함수는 보조 관찰이다. 실제 말하기 속도·발음·명료도를 검증한 점수로 해석하지 않는다.

발음·억양·원음 명료도, 감정/인성, 시선·표정·전신 태도, 입퇴장 행동, 합격 확률은 이 API 결과에 포함하지 않는다. 시선/표정 같은 관찰 기능을 추가하더라도 정직성·능력·채용 적합성 추론으로 확장하지 않는다.

## 호출 제한·중복 방지·비용

- 전사와 피드백을 합쳐 서버 프로세스당 최근 1시간 **최대 12회**. 최대 동시 호출 1개.
- 제공자 실패/불확실 결과도 시도 횟수에 포함한다. 자동 품질 재시도나 다른 모델로의 자동 fallback은 없다.
- 같은 엔드포인트·UUID·동일 입력은 10분 동안 같은 Promise/결과를 공유한다. 같은 UUID에 다른 입력이면 409다.
- 10분 후에는 원문 결과를 능동 해제하되 1시간까지 해시/UUID 표시를 남겨 같은 ID를 자동 재청구하지 않는다. 이 기간의 재요청은 `RESULT_EXPIRED`로 거절한다.
- 1시간 이후 또는 새 UUID는 새 호출이다. 서버 재시작·다중 프로세스에서는 현재 제한/중복 방지가 공유되지 않는다.
- 출력 토큰 상한은 비용 위험을 줄이는 제한이며, 원화 환율·모든 부대비용·유저 누적 사용량을 정산하는 장치는 아니다.

따라서 **평균 5천 원 전후/최대 1만 원**이라는 상품 목표가 이번 코드로 강제되는 것은 아니다. 현재는 관리자 로컬 테스트를 위한 임시 호출 방어선이다. 출시 전에는 영구 원가 원장, 선예약 예산, 실제 토큰/음성 길이 정산, 실패·취소·중복 청구 정책, 환율/단가 버전, 사용자/상품별 할당량이 필요하다.

## 검증 기록

- 신규 도메인/API 테스트 26개 통과: 동의/전사 확인, 관리자/운영/루프백/Origin/Host 별칭, 본문 상한, Structured Outputs, 인용/숫자 검증, 거절/불완전 응답, 중복/충돌/동시성/시간당 제한, 10분 결과 삭제/1시간 표시 삭제, WAV 검증, 비정상 STT.
- 이 범위 ESLint 및 전체 `tsc --noEmit` 통과.
- 실제 개발 서버의 `localhost:3000`과 `127.0.0.1:3000` 상태 조회 HTTP 200 확인. 비인증은 `/MAIL` 관리자 안내 반환.
- root 통합 확인: 인증된 GET 상태는 `authorized/configured/enabled=true`, Astra/Whisper 설정 확인. 브라우저 비인증 상태는 관리자 로그인 안내 확인. 비밀값은 출력하지 않았다.
- **실제 유료 OpenAI 전사→Astra 통합 호출은 미실행.** 라이브 모델 권한·한국어 전사 정확도·실제 답변 평가 품질·실제 토큰/원가·발음 분석 정확도는 검증 완료라고 쓰지 않는다.

## 다음 구현 경계

1. 사용자가 동의한 소수의 실제 음성/답변으로 유료 통합 테스트를 별도 승인받고 실행. 전사 수정 전후와 답변 유형별 품질 fixture/eval 작성.
2. 영구 실행/원가 원장과 사용자별 권한, 지원 케이스/문항/문서 Snapshot 연결. 재시작·재요청·실패에서 중복 청구를 방지하는 운영 계약.
3. 관리자 프롬프트/루브릭의 서버 버전 관리·검증·승인·롤백. 기존 참고 초안을 보존하고 선택 없이 실행판을 대체하지 않는다.
4. 10관점 평가를 구현하려면 관점별 독립 근거·상충 의견·합의 방법·중복 평가 편향·비용을 검증한다. 10개의 가짜 사람을 실제 인간 심사자로 홍보하지 않는다.
5. 실제 라이브 대화/끼어들기/지원자 역질문/동적 꼬리질문은 세션 상태·음성 턴·타이밍을 가진 별도 상호작용 엔진이 필요하다. 결과의 예상 꼬리질문 목록만으로 라이브가 구현된 것은 아니다.
6. 발음/원음 전달력은 음성을 직접 평가하는 별도 모델/기준/동의/실측 검증이 필요하다. STT 오류율 또는 피치 그래프를 발음 점수로 치환하지 않는다.
7. 영상/자세 관찰과 답변 내용 결과를 합칠 때에는 실제 프레임/시각/검출 한계가 있는 근거만 연결한다. 없는 영상 판단을 모델 문장으로 채우지 않는다.

## 무엇을 만들었나 (한 줄)

기존 웹앱 안에 **앱 전용 화면 `/app`**을 만들고, 이미 있던 **TWA(`com.mooaresume.twa`)의 시작 주소를 그 화면으로** 돌렸습니다. 입력·분류·문항·글자 수·저장·결제·분석은 웹에서 팔고 있는 그 구현을 그대로 씁니다.

## 왜 TWA인가 (WebView·재구현을 고른 것이 아닌 이유)

| 필요한 것 | TWA(Chrome) | WebView 래퍼 | 네이티브 재구현 |
|---|---|---|---|
| 기존 쿠키 로그인 | 그대로 동작 | 쿠키·세션 브리지 필요 | 별도 Bearer 체계(이미 `/api/mobile/*`에 있음, 두 벌 유지) |
| Google 로그인 | 동작 | **Google이 임베디드 WebView를 차단**(`disallowed_useragent`) | 동작 |
| 파일 첨부(PDF/DOCX/TXT/MD) | 브라우저 파일 선택 그대로 | 파일 선택기 연결 필요 | 다시 구현 |
| 결과 다운로드·인쇄(PDF) | Chrome 다운로드/인쇄 | 직접 처리 | 다시 구현 |
| Google Play 결제 | 이미 구현된 Digital Goods API 경로 | 네이티브 브리지 | `expo-iap`(별도 구현) |
| 새 의존성 | 없음 | `react-native-webview` 등 | Expo 전체 |

`apps/mobile`의 Expo 네이티브 시안(`com.mooaresume.app`)과 `/api/mobile/*`는 **지우지 않고 이전 variant로 보존**했습니다. `react-native-webview`는 설치하지 않았습니다.

## 화면 구조

- `/app` — 앱을 켜면 바로 넓은 간편 입력창. 위: QUICK / PRO / FINAL + 작성 유형(최종 첨삭·내용 보완·처음부터). 아래: 하단 탭바.
  - PRO/FINAL의 최종 첨삭·내용 보완 → `ProInputPage variant="app"`(기존 간편/상세 입력, 다중 첨부 자동 분류, 문항 구분, 문항별 목표 글자 수 전부 그대로)
  - QUICK → `QuickInputPage variant="app"`(기존 QUICK 입력. QUICK은 공고·이력서를 보지 않으므로 '처음부터'가 없습니다 — 기존 상품 범위와 동일)
  - '처음부터' → 기존 문답 마법사(`/pro/create`, `/final/create`)
  - FINAL은 `NEXT_PUBLIC_ENABLE_FINAL`이 꺼져 있으면 "준비 중"으로 고를 수 없습니다(기존 게이트 그대로).
- `/app/my` — 계정, 지난 분석 목록, 남은 이용권, 안내 문서. 새 API 없이 기존 RLS로 본인 것만 읽습니다.
- 하단 탭 4개: **첨삭(홈) · 이력서(`/resume`) · 커리어(`/career`) · 내 정보(`/app/my`)**. 탭바는 앱 셸에서만 보이고, 일반 웹 방문자에게는 렌더링되지 않습니다. 입력에 초점이 가면(키보드) 숨습니다.
- 지원서 이름은 입력 시작 때 묻지 않습니다(기존 자동 이름 로직 그대로: 회사명이 있으면 회사명, 없으면 "새 지원서").

## 입력 보존

앱은 탭으로 화면을 오가므로 입력 화면이 수시로 사라집니다. `variant="app"`일 때만 입력을 이 탭의 `sessionStorage`에 계속 저장하고(0.4초 디바운스) 돌아올 때 복원합니다(`src/lib/app-intake-draft.ts`). 저장 범위는 기존 게스트 초안과 같습니다 — 서버로 보내지 않고, 탭을 닫으면 사라집니다. 첨부가 많아 저장 한도를 넘으면 화면이 그 사실을 말합니다.

## 앱 컨텍스트 판단 (`src/lib/app-context.ts`)

두 가지를 나눠서 봅니다.

- **셸**: 이 탭이 `/app`을 거쳤는가 → 하단 탭바 표시만 결정.
- **설치 앱**: TWA로 실행됐는가(`?source=twa`, referrer `android-app://com.mooaresume.twa`, 또는 `getDigitalGoodsService` 존재) → 결제 수단 결정.

둘 다 권한이 아닙니다. 값을 흉내내도 바뀌는 것은 그 탭의 화면·결제 안내뿐이고, 분석 권한은 서버가 결제를 검증한 뒤에만 줍니다.

## Google Play 결제

흐름: **앱에서 구매 → 서버가 Play Developer API로 검증 → 이용권 지급 → (검증 통과 뒤에만) 구매 소비 → 기존 분석 실행**.

이번에 고친 것(기존 TWA 결제 코드에 빠져 있던 것):

1. **구매를 소비(consume)하지 않았습니다.** Play 소모성 상품은 소비해야 다시 살 수 있습니다 — 소비가 없으면 QUICK을 한 번 산 사람은 두 번째 지원서를 영영 결제할 수 없습니다. 이제 서버 검증이 이용권을 확인한 뒤에만 소비합니다(`src/lib/google-play/app-checkout.ts`).
2. **미완료 구매를 되살릴 방법이 없었습니다.** 결제 후 검증 요청이 끊기면 돈은 나갔고 분석 권한은 없는 상태였습니다. 이제 토큰·지원 건을 이 기기에 기록해 두고 다음 실행에서 확인해, 결제된 분석을 "추가 결제 없이 시작" 버튼으로 이어 줍니다.
3. **재시도가 막혀 있었습니다.** 이용권이 이미 지급된 실행은 `prepare_quick_checkout`이 `ACTIVE_ENTITLEMENT_EXISTS`로 거절하므로, 같은 토큰으로 다시 물어보면 영원히 "확인 실패"였습니다. 이제 서버가 **먼저** 그 토큰이 이미 지급된 건인지 보고, 같은 지원 건이면 `ALREADY_GRANTED`로 답해 앱이 구매를 끝낼 수 있게 합니다.
4. **한 결제를 여러 지원 건에 쓰려는 시도**는 409로 거절합니다(`GOOGLE_PLAY_PURCHASE_ALREADY_APPLIED`).
5. **결제 대기(pending)와 취소를 구분**합니다. 대기는 확인·소비하지 않고 "승인되면 추가 결제 없이 이어집니다"로 안내합니다.
6. **KR 외 스토어 결제는 승인(acknowledge) 전에 거절**합니다 — 원장이 KRW 카탈로그 기준이므로 해외 결제를 KRW 매출로 기록하지 않습니다. 승인하지 않으면 Play가 자동 환불합니다. 클라이언트도 상품 통화가 KRW가 아니면 결제창 자체를 열지 않습니다.
7. **앱 안에서 Play 결제를 못 쓰면 Polar로 우회하지 않습니다.** 정책 위반이고, 조용한 우회는 더 나쁩니다. 입력이 저장돼 있다는 사실과 함께 멈춥니다. 상품 사다리에 없는 분량도 앱에서는 "웹에서 결제하세요"라고 안내하지 않습니다(외부 결제 유도 금지).

기존 웹 Polar 경로와 TWA 없는 브라우저 동작은 바뀌지 않았습니다.

## 검증한 것 / 검증하지 않은 것

검증:
- 타입 검사 통과, ESLint 오류 0(기존 무관 경고 2), Vitest 152 파일 / 1200 테스트 통과(신규 28개 포함 — 앱 컨텍스트, 앱 입력 보존, Play 구매·복구·대기·중복·통화, 서버 검증 경계).
- 로컬 `next build` 통과.
- 실제 화면(390×844 상당, 로컬 dev): 앱 첫 화면의 상품·유형·입력, 붙여넣기 후 **이력서 탭 왕복 뒤 입력 유지**, 결제 화면 왕복 뒤 입력 유지, QUICK 전환, `/app/my`(비로그인), 입력 초점 시 탭바 숨김, 저장·결제 경계 화면까지 이동. 콘솔 오류 없음.
- 기존 웹 화면(`/quick`, `/pro/polish`)에 탭바가 생기지 않고 헤더·진행 순서 카드가 그대로임을 확인.

검증하지 않음(할 수 없었음):
- **실제 Google Play 구매·환불·복구**: Play Console 앱/인앱상품/테스트 트랙/서비스 계정·서버 환경변수가 없어 코드 경로만 테스트로 고정했습니다. 실구매 승인도 받지 않았습니다.
- **실기기 TWA 실행**: `/app`이 실서버에 배포되기 전에 APK/AAB를 만들면 앱을 켜자마자 404입니다. 그래서 `twa-manifest.json`의 `startUrl`만 `/app?source=twa`로 고치고 **빌드는 하지 않았습니다**. 배포 → `bubblewrap update` → 빌드 → 내부 테스트 순서입니다.
- 실제 유료 AI 호출, 원격 DB 변경, 배포, 스토어 업로드: 하지 않았습니다(별도 승인 사항).
- Android 뒤로가기·외부 링크·다운로드/공유는 Chrome 기본 동작에 의존합니다. 코드로 막거나 바꾼 것이 없고, 실기기 확인은 남아 있습니다.

## 남은 일

1. `/app` 배포 → TWA 재빌드 → 내부 테스트 트랙 업로드 → 실기기에서 로그인·입력·결제 1건.
2. Play Console 인앱상품 생성 + 서버 `GOOGLE_PLAY_*` 환경변수 + `NEXT_PUBLIC_GOOGLE_PLAY_*_PRODUCT_ID` 설정. `assetlinks.json`에 Play App Signing 지문 **추가**(기존 업로드 키 지문은 지우지 않음).
3. **모의면접 재시도(3,000원) Play 구매도 같은 소비 누락이 있습니다** — `src/app/api/interview/retry/google-play/verify/route.ts`와 `interactive-interview.tsx`는 이번 범위에 넣지 않았습니다. 앱에서 재시도를 두 번 사려면 같은 방식으로 고쳐야 합니다.
4. 앱 안에서 `/analysis/prepare`의 "상품 선택으로" 링크는 여전히 웹 `/onboarding`으로 갑니다. 안드로이드 뒤로가기로 돌아올 수 있어 급하지 않지만, 앱에서는 `/app`으로 보내는 것이 맞습니다.
5. 스토어 출시에 필요한 것(앱 개인정보·데이터 세이프티·삭제 흐름·스크린샷)은 그대로 남아 있습니다.

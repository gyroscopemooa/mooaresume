# 관리자 수동 첨삭 시험

## 범위

`/meensoo/analyses/[분석 ID]`의 **관리자 수동 첨삭 시험**에서 조회·자료 준비·유료 단계 실행을 각각 누른다. 고객 결과/분석 상태/결제/이용권을 쓰는 경로는 없다. 자동 스케줄·자동 재구매·고객용 반영 버튼도 없다.

- 재작성: 저장된 첫 작성안과 거절 사유를 참고해 해당 답변 전체의 새 후보를 만든다.
- 문장 단위: 원문에 유일하게 등장하는 한 문장을 정확히 지정한 교정만 허용한다. 부분 문자열, 없는 인용, 겹치는 교정, 문장 합치기/재배열은 거절한다.
- 공통: 수정별 독립 호출 검토 → 채택된 수정만 실제 조합 → 그 **조합 전체**를 별도 호출로 검토. 단일 AI의 판단이므로 품질 보장이나 전문가 승인으로 표시하지 않는다.

이는 `admin-editing-1` 실험 프로토콜이다. 기존 운영 재작성 토글의 완전한 재현이 아니며, 여기서 좋아졌다고 기존 토글을 그대로 켜도 된다고 결론낼 수 없다. 고객에게 이미 제공한 결과를 비교 기준으로 함께 표시한다. 모의시험 결과가 안전하지 않거나 실질 개선이 없으면 최종 개선 미채택으로 표시한다.

## 대상과 입력

- 완료된 QUICK/POLISH, 최초 입력(`relationship=new`)만.
- 현재 버전의 연구 활용 동의와 `research_snapshots` 사본이 모두 존재해야 한다.
- 문항 간 충돌이 없고, 사실/목소리 손실 또는 새 오류 때문에 수정안이 거절되어 원문을 유지한 문항만. 단순 취향/재등장 문제는 제외.
- 완료 후 `analysis_runs.response_id`에 남는 작성 ID와 결과의 `revisionQuality.reviewerResponseId`로 실제 저장된 API 응답을 조회한다(검토 커서 형태도 일치 여부 검사 후 지원). 없는/만료된 자료를 새 유료 작성으로 대체하지 않는다. 과거 프롬프트 버전도 기록한다.
- 기존 질문 분리 함수를 재사용. 원문·제공본·거절안·거절 사유와 지원 회사/직무, 문체/첨삭 기조, 저장된 공고/증빙/추가 경험 및 맥락 조사 결과를 사용한다. 입력은 총 JSON 40,000자 초과 시 차단한다.
- 이름(알고 있는 프로필 이름), 연락처 등의 기존 비식별 함수 적용 후 관리자에게 **실제 전송 입력**을 보여준다. 비식별은 완전한 익명화가 아니므로 남은 개인정보를 확인하지 않았으면 실행하면 안 된다. 생성 결과도 연락처 등의 패턴을 다시 제거한다.

## 비용·중복 방지

- 자료 준비는 기존 응답 GET만 수행한다. 실제 비용 있는 생성/검토는 별도 확인 후 POST한다.
- 한 단계당 한 번의 백그라운드 AI 호출, 최대 출력 12,000토큰. 한 방식의 전체 시험은 최대 3단계. 두 방식은 별도 과금된다.
- 각 단계마다 관리자가 클릭한다. 조회로 다음 유료 단계가 자동 실행되지 않는다.
- `(snapshot_id, mode, protocol_version)` 유일 키, DB 상태 CAS 및 요청의 `expectedState`로 중복 클릭과 오래된 요청을 차단한다.
- 접수/응답 ID 저장이 불확실하면 `UNCERTAIN`. 자동 재시도 금지. 운영자가 API 사용 기록과 서버 상태를 먼저 확인해야 한다. 접수 상태에서 서버가 죽으면 2분 후 수동 조회로 불확실 상태를 표시한다.
- 실패/거절 응답도 사용량이 제공되면 기록한다. 미확인 토큰/비용은 0으로 표시하지 않는다. 현재 화면은 확인된 **추가 토큰**을 표시하며, 원화 확정 청구액을 계산하는 기능은 없다.

## 개인정보·운영 활성화 전 보류

현재 선택 동의는 비식별 사본의 품질 개선 활용을 설명하지만, **별도 관리자 AI 실험·공급자 응답 저장까지 그 범위로 운영할지 확인이 필요하다.** 기존 동의를 임의로 확대하거나 문구 버전을 자동 변경하지 않는다. 동의 안내 변경이 필요하면 별도 사용자 결정 후 새 버전으로 다시 동의받아야 한다.

그래서 `ADMIN_EDITING_EXPERIMENTS_ENABLED=on` 없이는 자료 준비·유료 실행을 하지 않는다. 기존 `QUICK_REVISION_REPAIR`와 무관한 별도 플래그다.

활성화 순서:

1. 위 개인정보 처리 범위 승인/필요시 동의 문구 및 버전 변경.
2. 신규 마이그레이션 `20261007020000_admin_editing_experiments.sql`을 별도 DB에서 적용해 트리거·RLS·철회/삭제를 실행 검증.
3. 앱 배포와 마이그레이션 적용. 운영 DB 변경·플래그 활성화는 별도 승인 후 진행.
4. 합성/허가된 시험 자료로 실제 API 스키마 수용·전체 3단계·비용 기록 확인(유료).
5. 관리자 수동 사용. 자동 실행으로 전환하지 않는다.

새 시험 테이블은 연구 사본/분석/계정 삭제에 cascade된다. 동의 철회·문구 버전 변경·동의 행 삭제 시 시험 기록도 삭제한다. 요청마다 동의를 재확인하고 DB 트리거에서도 동의/소유자/버전을 검사한다. 삭제 후 진행 중 요청이 결과를 다시 저장할 수 없다. 이미 외부로 전송된 비식별 요청을 철회로 소급 취소했다고 주장하지 않는다.

## 롤백

플래그를 끄면 새 실험 진행이 차단된다. 고객 분석은 원래 경로 그대로다. 앱 소스 복구 기준은 `4a7ec88`. 새 테이블 삭제는 별도 파괴적 작업이므로 자동 수행하지 않는다.

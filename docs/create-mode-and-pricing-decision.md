# MOOA Resume — CREATE 모드 및 상품 경계 결정

> 결정일: 2026-08-15  
> 상태: 최신 제품 결정  
> 관련 문서: `MOOA_RESUME_PROJECT_SPEC.md`, `MOOA_RESUME_ADDITIONAL_SPEC.md`  
> 우선순위: 동일 항목이 충돌하면 이 문서의 결정이 우선

## 1. 논의 배경

MOOA Resume 사용자는 다음 세 상태로 나뉜다.

1. 아무것도 작성하지 않은 사용자
2. 초안은 있지만 내용과 근거가 부족한 사용자
3. 거의 완성했고 제출 전 검수가 필요한 사용자

기존 추가 명세에서는 CREATE / BUILD / POLISH 모두 QUICK과 PRO에서 이용할 수 있도록 제안했다. 그러나 QUICK을 “작성한 자소서를 간단한 입력칸에 넣고 첨삭받는 상품”으로 정의하면, 작성된 원문이 없는 CREATE는 QUICK에서 성립하기 어렵다.

## 2. 최신 결정

### QUICK — 작성한 글 첨삭

QUICK은 첨삭할 원문이 있는 사용자를 위한 상품이다.

- 지원서 원문 필수
- BUILD 또는 POLISH 이용 가능
- 작성 중인 글의 내용 보완
- 문항 충족, 구체성, 논리, 표현, 가독성 검사
- 맞춤법, 띄어쓰기, 글자 수 확인
- Before/After
- 수정 이유
- 공고, 이력서, 경력기술서 교차분석은 제한

QUICK에서는 원문이 전혀 없는 CREATE를 제공하지 않는다.

### PRO — 기업 지원서 전체 코칭

PRO는 하나의 기업 지원 과정을 전체적으로 지원한다.

- CREATE / BUILD / POLISH 모두 이용 가능
- 원문이 없어도 채용공고와 사용자 자료를 기반으로 시작 가능
- 채용공고 분석
- 이력서, 경력기술서, 포트폴리오, 경험은행 참고
- 경험 후보 추천
- 부족한 사실에 대한 추가 질문
- 소재 선정
- 개요 작성
- 사용자 확인 후 초안 작성
- 여러 문항의 경험 배치 및 중복 확인
- 공고 적합성 및 자료 교차검증
- 최종 첨삭
- 면접 예상 질문

## 3. 사용자 진입 흐름

```text
작성한 지원서가 있나요?

예
├─ 작성한 글을 빠르게 다듬고 싶어요
│  └─ QUICK
│
└─ 공고와 지원자료 전체를 함께 분석하고 싶어요
   └─ PRO

아니요
└─ 경험과 소재 선정부터 처음 작성하고 싶어요
   └─ PRO / CREATE
```

상품명보다 사용자의 현재 상태와 원하는 결과를 먼저 묻는다.

## 4. CREATE 진행 방식

CREATE는 ChatGPT처럼 목적 없이 계속 대화하는 무제한 자유 채팅으로 만들지 않는다.

화면은 대화형일 수 있지만 내부적으로 단계가 정해진 **대화형 작성 인터뷰**로 설계한다.

```text
채용공고·지원 문항 확인
↓
이력서·경력·경험 자료 확인
↓
활용 가능한 경험 후보 추출
↓
사용자가 소재 선택
↓
부족한 사실만 추가 질문
↓
AI가 확인된 사실 요약
↓
사용자가 사실관계 승인
↓
문항 개요 제안
↓
사용자가 개요 승인
↓
검증된 사실만으로 초안 작성
↓
글자 수·말투·공고 적합성 검수
```

## 5. CREATE 상호작용 원칙

- 기존 자료에서 확인 가능한 내용을 반복해서 묻지 않는다.
- 한 번에 많은 질문을 보여주지 않고 필요한 질문을 1~3개씩 진행한다.
- 사용자가 제공하거나 승인하지 않은 경험, 역할, 성과, 수치, 날짜를 생성하지 않는다.
- AI가 이해한 사실을 초안 작성 전에 사용자에게 확인받는다.
- 결과가 확인되지 않으면 `확인 필요` 상태로 남긴다.
- 사용자가 답변하기 어려운 질문은 건너뛸 수 있다.
- 작성 목적을 벗어난 일반적인 무제한 AI 채팅은 제공하지 않는다.

## 6. CREATE 점수 표시

작성된 원문이 없는 상태에서는 지원서 준비도 점수를 표시하지 않는다.

대신 다음 정보를 제공한다.

- 확인된 경험
- 추천 소재
- 아직 필요한 정보
- 현재 작성 단계
- 다음 행동

초안이 만들어지고 사용자가 사실관계를 확인한 이후에만 동일 Rubric으로 준비도를 평가한다.

## 7. 가격 기준

가격은 대화 시간이나 메시지 수가 아니라 **완성 범위**를 기준으로 한다.

사용자에게 판매하는 기준:

```text
AI와 몇 회 대화
```

가 아니라:

```text
QUICK = 작성한 지원서의 첨삭
PRO   = 기업 지원서 한 건의 전체 코칭
```

### QUICK 기준안

- 기존 가격 초안: 4,900원
- 작성된 지원서 원문 필요
- 정해진 문항 또는 분량의 분석과 첨삭
- 수정본과 수정 이유 제공

### PRO 기준안

- 기존 가격 초안: 9,900원
- 하나의 `ApplicationCase`, 즉 기업 지원 한 건 기준
- CREATE 사용자는 경험 확인부터 초안과 최종검수까지 포함
- BUILD/POLISH 사용자는 공고와 전체 지원자료 교차분석 포함

가격 숫자는 실험 가능하지만 QUICK과 PRO의 기능 경계는 유지한다.

## 8. 내부 비용 및 남용 방지

사용자에게 메시지 수를 핵심 상품 가치로 노출하지 않더라도 내부적으로 다음 경계를 둔다.

- 하나의 ApplicationCase 범위
- 지원 문항과 입력 문서의 합리적인 개수
- 추가 질문 단계의 최대 반복 수
- 초안 및 수정본 생성 횟수
- 재분석 가능 기간
- 입력 길이와 총 토큰 제한
- 동일 질문과 답변의 반복 감지
- 지원서 작성 범위를 벗어난 일반 상담 제한

구체적인 제한값은 실제 API 비용, 완료율, 사용자 이탈 데이터를 확인한 뒤 결정한다.

## 9. 기존 추가 명세에서 변경되는 부분

`MOOA_RESUME_ADDITIONAL_SPEC.md`의 다음 기존 결정:

```text
QUICK
- 현재 자소서/텍스트 중심
- CREATE / BUILD / POLISH 모두 가능
```

은 이 문서의 최신 결정으로 대체한다.

```text
QUICK
- BUILD / POLISH 가능
- 작성된 원문 필수

PRO
- CREATE / BUILD / POLISH 가능
- CREATE는 대화형 작성 인터뷰 제공
```

## 10. 구현 영향

- `/start`에서 작성 원문 유무를 먼저 확인한다.
- CREATE로 판별되면 QUICK을 비활성화하고 이유를 설명한다.
- CREATE는 PRO 작성 인터뷰 화면으로 이동한다.
- BUILD와 POLISH는 QUICK/PRO 중 원하는 분석 범위를 선택할 수 있다.
- 가격표에서 QUICK은 첨삭, PRO는 기업 지원 전체 코칭으로 설명한다.
- 분석 entitlement는 메시지 횟수가 아니라 ApplicationCase와 결과물 범위를 기준으로 설계한다.

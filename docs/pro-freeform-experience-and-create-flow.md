# PRO 자유입력, 작성 스타일과 CREATE 흐름 결정

작성일: 2026-08-16

## 결정

CREATE, BUILD, POLISH는 같은 PRO 입력 화면과 상품 경계를 공유한다. 다만 내부 작성 메커니즘은 작성 상태에 따라 분리한다.

모든 PRO 유형에 `추가로 알려주고 싶은 경험·정보` 자유입력란을 선택 항목으로 제공한다. 자유입력을 기본으로 노출하고, 기존 구조화 입력은 `경험을 하나씩 자세히 추가하기` 안에 선택 기능으로 유지한다.

## 공통 PRO 입력 구조

1. 채용공고: 링크, 본문 또는 파일
2. 현재 자기소개서: 전체 붙여넣기 또는 파일. CREATE는 작성본 없음 상태를 명시
3. 지원자료: 이력서, 경력기술서, 포트폴리오, 기타 파일
4. 추가 경험·정보: 형식 없는 자유입력
5. 경험·자격·스펙 상세 입력: 원하는 사용자만 선택

자유입력 예시는 면허, 아르바이트, 해외 체류, 프로젝트, 학교 활동, 군 복무처럼 사용자가 중요도를 판단하기 어려운 경험까지 포함한다.

## CREATE 메커니즘

```text
공고 + 지원자료 + 추가 경험·정보
→ 원문에서 사실과 경험 후보 구조화
→ 문항별 추천 소재 제시
→ 중요한 사실이 충분하면 바로 개요 및 초안 제안
→ 중요한 사실이 부족할 때만 정보 이득이 큰 질문 2~4개
→ 필요한 해석과 사용자 사실 확인
→ 확인 결과를 반영한 초안 생성
→ 교차검증과 최종 검수
```

CREATE는 가진 정보가 충분하면 바로 초안을 제안할 수 있다. 다만 자유입력을 먼저 사실과 경험 후보로 구조화하며, 확인되지 않은 사건·역할·성과를 확정하지 않는다. 질문은 초안 작성에 중요한 사실이 부족할 때만 사용한다.

## BUILD 및 POLISH 메커니즘

```text
현재 자기소개서 + 공고 + 지원자료 + 추가 경험·정보
→ 현재 글 진단
→ 더 적합한 경험 또는 빠진 근거 탐색
→ 필요한 사실만 질문
→ 기존 글을 보존하며 보완 또는 첨삭
→ 교차검증과 최종 검수
```

BUILD/POLISH에서도 자유입력 경험은 기존 자기소개서보다 더 적합한 소재를 찾는 후보로 사용한다.

## 사실 안전 규칙

- 자유입력 원문은 곧바로 자기소개서 문장에 사용하지 않는다.
- AI가 경험 후보로 분리하고 날짜, 기간, 목적, 역할, 행동, 결과의 확인 상태를 기록한다.
- 확인되지 않은 필드는 `needs_verification`으로 유지한다.
- 공고 적합도와 예상 정보 이득이 높은 경험만 추가 질문 대상으로 고른다.
- 한 번에 묻는 질문은 2~4개로 제한한다.
- 사용자 확인 전 새 사건, 수치, 역할, 성과 또는 내면의 의미를 확정하지 않는다.

## 현재 구현 범위

- 공통 PRO 후보자료 스키마에 최대 12,000자의 `freeformNotes`를 추가했다.
- 과거 세션 데이터에는 빈 문자열 기본값을 적용해 호환성을 유지한다.
- CREATE, BUILD, POLISH가 같은 PRO 입력 컴포넌트를 사용한다.
- CREATE에서는 자기소개서 입력 대신 경험 탐색과 사실 확인 안내를 표시한다.
- 기존 자격·스펙·경험 상세 입력은 접힌 선택 영역으로 유지한다.
- 자유입력 영역은 직접 입력과 PDF·DOCX·TXT·MD 다중 첨부를 같은 Composer에서 받는다.
- 첨부파일 원문은 직접 입력 메모와 합치지 않고 파일별 출처로 분리해 저장하며, 파일 제거 시 해당 원문도 함께 제외한다.
- 채용공고 Composer는 동일한 올인원 입력 방식을 유지하되 화면 밀도를 위해 기본 높이를 축소한다.
- CREATE 워크플로 상태에 `rawAdditionalInfo`를 별도로 보존한다.
## Writing Mode와 Writing Style

두 선택은 서로 다른 축으로 관리한다.

- **Writing Mode**: 현재 작성 상태. CREATE / BUILD / POLISH
- **Writing Style**: AI가 제공된 사실 안에서 경험의 의미와 직무 연결을 얼마나 적극적으로 구성할지 결정

사용자 선택지는 다음과 같다.

| 사용자 명칭 | 내부 값 | Narrative Latitude | 동작 |
| --- | --- | ---: | --- |
| 담백하게 | CONCISE | 1 | 사실 중심으로 간결하게 구성하고 해석을 최소화 |
| 균형 있게 | BALANCED | 2 | 사실을 유지하며 경험의 의미와 직무 연결을 자연스럽게 발굴 |
| 강점 살리기 | STRENGTH_FOCUSED | 3 | 같은 사실 안에서 강점·배운 점·직무 연관성을 적극적으로 제안 |

**균형 있게**를 기본값이자 추천값으로 사용한다. 섬세함은 선택 스타일이 아니라 모든 결과에 적용되는 제품 품질 기준이다. 부풀리기처럼 허위 작성을 연상시키는 표현은 사용하지 않는다.

## 모드별 적용

- CREATE: 경험의 의미, 문항별 소재와 전체 구조를 적극적으로 제안할 수 있다.
- BUILD: 기존 글에서 빠진 근거를 찾고 더 좋은 소재로 교체하거나 크게 재구성할 수 있다.
- POLISH: 강점 살리기를 골라도 기존 말투와 좋은 문장의 보존이 우선이다. 유효 Narrative Latitude는 최대 2로 제한한다.

## CREATE 질문 원칙 변경

CREATE는 무조건 질문부터 시작하지 않는다.

~~~text
가진 정보로 최대한 경험과 초안을 구성
→ 중요한 사실이 충분하면 바로 초안 제안
→ 중요한 사실이 부족할 때만 정보 이득이 큰 질문 2~4개
→ 확인된 답변 반영
→ 최종본 확정
~~~

지원자가 제공한 사실에서 직접 뒷받침되는 의미 연결은 허용한다. 예를 들어 편의점 야간 교대근무를 정확한 인수인계와 업무 연속성의 소재로 제안할 수 있다. 다만 사용자의 내면, 실제 행동 또는 결과로 확정하려면 근거가 있거나 사용자 확인이 필요하다.

## 불변 안전선

작성 스타일은 사실 생성 허용 수준이 아니다. 어떤 스타일에서도 제공되지 않은 경험, 역할, 사건, 고용관계, 기간, 수치, 성과를 만들지 않는다. 강점 살리기는 사실의 의미와 배치를 적극적으로 제안하는 옵션이지 허위 내용을 허용하는 옵션이 아니다.

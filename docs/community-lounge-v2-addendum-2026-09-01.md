# 커뮤니티 라운지 V2 추가 기획 — 읽기 우선·안전한 최소 씨앗

작성일: 2026-09-01

상태: **추가 기획 초안 · 구현 승인 아님**
대상: 현재 `/community` 기초 라운지의 다음 판단 기준

## 1. 이 문서가 하는 일

현재 라운지는 실제 게시판이 아니라, 취업·진로 고민의 예시를 읽고 커리어 검사로 이동하는 공개 기초 화면이다. 이 문서는 그 화면을 무작정 SNS나 익명 커뮤니티로 키우지 않고, 사용자가 다음 행동을 정리할 수 있는 `읽기 우선 라운지`로 발전시키기 위한 추가 기준이다.

기존 `career-assessment-roadmap.md`의 결정(실사용자 누적 뒤 최소 씨앗 기능 검토)과 `mooa-resume-career-v1-v2-reconciliation-2026-08-27.md`의 결정(현재 구현하지 않음)을 대체하지 않는다. 둘과 충돌하면 기존 문서와 제품 안전 경계를 우선한다.

## 2. 현재 확인된 기준선

- 경로: `/community`
- 제공: 주제 선택, 예시 고민 피드, 개인정보 보호 약속, 커리어 검사 CTA
- 미제공: 글쓰기, 댓글, 좋아요, 사용자 프로필, 저장, 알림, 실제 게시물 DB
- 현재 예시 데이터는 `src/domain/community-lounge.ts`에 분리되어 있어 실제 데이터 도입 전 교체 가능하다.

따라서 지금 화면의 `익명 고민 남기기 준비 중`은 기능 약속이 아니라, 안전 장치와 운영 기준이 갖춰질 때까지의 명확한 보류 표시다.

## 3. 참고자료 확인 상태

- 사용자가 공유한 ChatGPT 대화 링크는 이 작업 환경에서 직접 열리지 않아 전문을 확인하지 못했다.
- 워크트리의 커밋·문서·파일명에서 `코인니스`라는 명시적 기록이나 해당 스크린샷은 찾지 못했다. 커리어 결과 화면 캡처만 남아 있다.
- 그러므로 이 문서는 특정 서비스 화면을 복제했다거나, 공유 대화의 세부 요구를 모두 반영했다고 주장하지 않는다.
- 대화 원문 또는 스크린샷이 다시 제공되면 아래 UX 가설을 그 자료와 대조해 별도 개정한다.

## 4. V2의 제품 방향

### 읽기 우선

처음에는 콘텐츠를 읽고 `나도 이런 고민이 있다`고 분류하는 경험이 중심이다. 글을 많이 쓰게 만드는 구조보다, 고민을 유형화하고 다음 행동으로 이어 주는 구조를 우선한다.

### 정보 밀도는 높되 과열은 만들지 않기

참고 서비스의 화면처럼 주제·제목·핵심 맥락을 빠르게 훑는 피드형 정보 구조는 검토할 수 있다. 단, 실시간 인기순위, 과도한 반응 수, 자극적 제목 경쟁, 합격 인증 비교는 만들지 않는다. 취업 준비 서비스에서 불안과 비교를 키우는 장치가 될 수 있기 때문이다.

### 커리어 도구와 자연스럽게 연결

각 고민은 답을 단정하지 않고, 직업흥미·업무성향·가치관·지원서 경험 정리 중 지금 필요한 다음 행동 하나로 연결한다. 검사 결과나 지원서 내용은 절대 커뮤니티에 자동 공개하지 않는다.

## 5. 화면 발전 순서

### 단계 A — 현재 공개 미리보기 유지

- 예시 글과 주제 필터만 제공
- 예시임을 분명히 표시
- 로그인 없이 읽기 가능
- 글쓰기 버튼은 비활성 상태 유지

### 단계 B — 실제 글쓰기 전, 검토 가능한 시안

구현 전에 다음 화면만 시안으로 검토한다.

1. 상단: 전체 · 취업 준비 · 직무·진로 · 자소서·면접 · 회사생활
2. 목록: 주제, 한 줄 제목, 고민 맥락 2줄, 작성 시점만 표시
3. 상세: 상황 → 이미 해 본 것 → 지금 막힌 지점 → 다음 행동 카드
4. 작성 진입: 익명 원칙·금지 정보·신고 기준을 먼저 읽는 화면

이 단계에서도 DB·댓글·실제 게시물은 만들지 않는다.

### 단계 C — 실제 최소 게시판을 열 수 있는 조건

아래 조건을 모두 만족하기 전에는 실제 글쓰기와 댓글을 열지 않는다.

- 로그인 사용자와 익명 표시의 관계가 명확함
- 실명, 연락처, 회사 내부정보, 제3자 개인정보를 막거나 신고·삭제할 수 있음
- 신고, 숨김, 운영자 검토, 차단, 기본 레이트리밋이 설계됨
- 게시물·댓글·신고 데이터의 RLS와 삭제 정책이 검토됨
- 합격 보장, 의료·심리 진단, 법률·노무 단정, 혐오·괴롭힘 대응 기준이 마련됨
- 운영 담당자와 응답 시간 기준이 정해짐

## 6. 콘텐츠 원칙

- `정답 직무`, `합격 가능성`, `이 회사는 무조건 피하라` 같은 단정형 조언을 추천하지 않는다.
- 사용자의 지원서, 검사 결과, 파일은 명시적으로 선택하지 않는 한 게시물에 인용하거나 노출하지 않는다.
- 예시와 실제 글을 시각적으로 확실히 구분한다.
- 반응 수가 적은 새 글이나 민감한 고민을 인기순위에서 불리하게 만들지 않는다.
- AI가 게시자를 흉내 내거나 실제 사용자 경험담을 생성하지 않는다. AI가 쓰인다면 신고 분류·개인정보 경고·다음 행동 정리처럼 보조 역할만 검토한다.

## 7. 다음 결정이 필요한 것

1. 라운지를 장기적으로 공개 읽기 전용으로 둘지, 로그인 기반 최소 글쓰기까지 열지
2. 첫 실제 카테고리를 취업 준비 중심으로 좁힐지, 회사생활까지 한 번에 포함할지
3. 코인니스/참고 스크린샷에서 가져오고 싶은 것이 목록 밀도인지, 탭 구조인지, 카드 톤인지
4. 운영·신고 담당과 삭제 기준을 누가 맡을지

이 네 가지가 정해지기 전에는 현재 라운지를 넘어선 DB, API, 댓글, 알림, 추천 알고리즘을 구현하지 않는다.

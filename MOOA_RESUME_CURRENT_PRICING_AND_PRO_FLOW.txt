MOOA Resume 현재 가격·상품·PRO 유형별 플로우 정리
작성일: 2026-08-15
상태: 현재 대화 기준 최신 결정 요약

======================================================================
1. 이번에 다시 정리하는 이유
======================================================================

사용자 작성 상태는 세 가지다.

1) CREATE  : 아직 아무것도 작성하지 않음
2) BUILD   : 일단 작성했지만 내용과 근거가 부족함
3) POLISH  : 거의 완성했고 제출 전 최종 확인이 필요함

상품은 작성 상태와 별개다.

1) QUICK 4,900원
2) PRO   9,900원
3) FINAL 14,900원 — 향후 구현, 현재 Coming Soon 가능

CREATE / BUILD / POLISH를 각각 다른 가격 상품으로 판매하지 않는다.
사용자의 현재 상태에 따라 같은 상품 안에서도 시작 위치와 진행 단계가 달라진다.

======================================================================
2. 현재 가격 구조
======================================================================

[QUICK — 4,900원]

한 문장 정의:
이미 작성한 자기소개서를 빠르고 정확하게 첨삭하는 상품.

이용 가능:
- BUILD
- POLISH

이용 불가:
- CREATE

QUICK 제공 범위:
- 작성한 자기소개서 입력 또는 파일 업로드
- 맞춤법과 문법
- 문장 표현과 가독성
- 논리와 구체성
- 반복 표현 및 추상적인 표현
- 글자 수
- 핵심 개선점 3개
- 문장별 피드백
- 수정 이유
- Before → After
- 최종 수정본

QUICK에서 하지 않는 것:
- 처음부터 경험 발굴
- 채용공고 전체 분석
- 이력서와 경력기술서 교차분석
- 문항별 소재 전략
- 공고 요구역량 매칭
- 지원서 전체 문항의 경험 배치
- 정밀 면접 리스크 분석


[PRO — 9,900원]

한 문장 정의:
채용공고와 지원자료 전체를 보고, 현재 작성 상태에서 시작하여 최종 제출 전 검수까지 지원하는 기업 지원서 1건 단위 상품.

이용 가능:
- CREATE
- BUILD
- POLISH

PRO 공통 범위:
- 하나의 Application Case, 즉 기업·직무·채용공고 지원 1건
- 채용공고 분석
- 자기소개서 여러 문항
- 이력서, 경력기술서, 포트폴리오, 추가 경험 활용
- 공고 요구역량 추출
- 경험과 공고 매칭
- 문항별 경험 배치
- 문항 간 경험 중복 검사
- 자료 간 충돌 검사
- 누락된 근거 확인
- 최종 수정본
- 제출 전 최종검수
- 실제 지원자료 기반 면접 예상 질문


[FINAL — 14,900원]

현재는 향후 상품이다.

예상 범위:
- PRO 전체
- 인터랙티브 텍스트 모의면접
- 동적 꼬리질문
- 답변 평가
- 취약 질문 재훈련

FINAL 전체 기능이 구현되기 전에는 Coming Soon으로 표시할 수 있다.

======================================================================
3. 같은 PRO라도 유형별 플로우는 서로 다르다
======================================================================

중요:

CREATE의 PRO와 POLISH의 PRO는 같은 9,900원 상품이지만 같은 화면과 같은 순서로 진행하면 안 된다.

같은 이유:
- 둘 다 기업 지원서 한 건 전체를 다룬다.
- 채용공고와 지원자료를 함께 분석한다.
- 최종 제출 전 검수까지 제공한다.
- 가격 단위가 대화 횟수가 아니라 Application Case 한 건이다.

다른 이유:
- CREATE는 작성할 내용 자체를 찾아야 한다.
- BUILD는 부족한 내용과 근거를 보강해야 한다.
- POLISH는 이미 있는 내용을 최대한 보존하며 교차검수해야 한다.


---------------------------------------------------------------------
3-1. CREATE + PRO
---------------------------------------------------------------------

대상:
- 자기소개서를 전혀 작성하지 않음
- 소재를 무엇으로 해야 할지 모름
- 공고와 이력서만 가지고 시작함

진행:

채용공고·직무·문항 확인
→ 이력서·경력·경험자료 확인
→ 활용 가능한 경험 후보 추출
→ 문항별 추천 소재 제안
→ 사용자가 사용할 경험 선택
→ 부족한 사실만 2~4개 묶어서 질문
→ 사용자가 문제 상황·직접 행동·결과 입력
→ AI가 확인한 사실을 요약
→ 사용자가 사실관계 승인
→ 문항 개요 생성
→ 개요 확인
→ 검증된 사실만으로 초안 생성
→ 사용자 수정 요청
→ 전체 문항 경험 중복검사
→ 공고 기준 최종검수
→ 면접 예상 질문

CREATE는 자유로운 ChatGPT 채팅이 아니다.

화면 형태:
- AI 안내 메시지
- 경험 후보 선택 카드
- 체크박스
- 구조화된 질문 입력칸
- 필요한 경우 자유입력

즉 Guided Conversation / Guided Interview 방식이다.


---------------------------------------------------------------------
3-2. BUILD + PRO
---------------------------------------------------------------------

대상:
- 초안은 있음
- 내용이 짧거나 추상적임
- 본인의 행동과 결과가 부족함
- 지원동기와 직무 연결이 약함

진행:

현재 초안 입력
→ 채용공고 분석
→ 이력서·경력자료에서 경험 추출
→ 현재 초안의 부족한 근거 탐지
→ 더 적합한 경험이 있으면 추천
→ 필요한 정보만 질문
→ 사용자가 사실 확인
→ 기존 초안을 보강 또는 재구성
→ Before → After
→ 수정 이유
→ 공고 기준 재검수
→ 최종 수정본
→ 면접 예상 질문

BUILD는 CREATE처럼 처음부터 모든 경험을 묻지 않는다.
이미 작성된 초안과 기존 자료에서 알 수 없는 정보만 질문한다.


---------------------------------------------------------------------
3-3. POLISH + PRO
---------------------------------------------------------------------

대상:
- 자기소개서가 거의 완성됨
- 제출 전 최종 확인이 필요함
- 공고와 이력서까지 함께 교차검증하고 싶음

진행:

완성된 지원서 입력 또는 파일 업로드
→ 채용공고 입력
→ 이력서·경력기술서 선택 업로드
→ 문항 충족과 글자 수 확인
→ 맞춤법·표현·논리 확인
→ 공고 요구역량과 지원서 연결 확인
→ 문항 간 경험 중복 확인
→ 이력서·경력기술서와 내용 충돌 확인
→ 기업명·직무명·기간·수치 오류 확인
→ 필요한 경우에만 확인 질문
→ 최소 수정 원칙의 최종 수정본
→ 면접에서 확인될 위험이 높은 내용
→ 예상 면접 질문

POLISH + PRO에서는 경험 발굴과 긴 작성 인터뷰부터 시작하면 안 된다.
바로 자료 업로드와 최종 교차검수 화면으로 이동해야 한다.

======================================================================
4. 현재 구현에서 바로잡아야 하는 부분
======================================================================

현재 프로토타입에서는 PRO 버튼이 유형과 관계없이 `/pro/create`로 연결되는 부분이 있다.

이것은 최종 제품 구조가 아니다.

최종 라우팅 권장:

CREATE + PRO
→ `/pro/create`

BUILD + PRO
→ `/pro/build` 또는 공통 `/pro` 내부 BUILD 단계

POLISH + PRO
→ `/pro/polish` 또는 공통 `/pro` 내부 POLISH 단계

QUICK + BUILD/POLISH
→ `/quick`

즉 PRO는 같은 상품이지만 WritingMode에 따라 다른 시작 화면으로 분기한다.

======================================================================
5. 아무것도 못 쓴 CREATE 사용자의 대화 상호작용 문제
======================================================================

사용자가 이전에 제기한 핵심 질문:

아무것도 작성하지 않은 사용자는 AI와 계속 대화를 주고받아야 하는가?
ChatGPT 같은 채팅 형식이라면 누구는 오랫동안 사용하고 누구는 짧게 끝날 텐데,
PRO 9,900원 같은 단건 가격을 어떻게 유지하는가?

결정:

CREATE는 상호작용형이지만 무제한 자유채팅으로 만들지 않는다.

이유:
- 사용자별 대화 시간이 크게 달라질 수 있음
- API 사용량과 원가를 예측하기 어려움
- 지원서 작성 범위를 벗어난 질문으로 이탈할 수 있음
- 어떤 사실이 최종 승인됐는지 추적하기 어려움
- 언제 서비스가 완료됐는지 불명확해짐
- 일반 ChatGPT와 제품 차이가 약해짐

해결 방식:

1. 자유채팅이 아니라 단계가 정해진 Guided Interview를 사용한다.
2. 하나씩 10번 질문하지 않고 관련 질문 2~4개를 묶어서 받는다.
3. 이미 이력서에서 확인 가능한 정보는 다시 묻지 않는다.
4. 사용자 답변을 구조화된 후보 사실로 저장한다.
5. 초안 생성 전 AI가 이해한 사실을 사용자에게 확인받는다.
6. 채팅 로그만으로 현재 진행 상태를 추론하지 않는다.
7. Application Case의 현재 Stage를 명시적으로 저장한다.

CREATE 진행 Stage:

JOB_ANALYSIS
EXPERIENCE_DISCOVERY
EXPERIENCE_SELECTION
FOLLOW_UP
OUTLINE
DRAFT
REVISION
FINAL_REVIEW
INTERVIEW_PREP

6. CREATE 가격을 대화 횟수로 정하지 않는 이유
======================================================================

사용자에게 판매하는 것은 다음이 아니다.

- AI 메시지 20회
- AI와 대화 30분
- 질문 10개

판매 단위:

- 현대자동차 2026 하반기 생산관리 지원서 1건
- 즉 Application Case 한 건

PRO 1건 안에서 가능한 것:
- 공고 분석
- 여러 자기소개서 문항
- 경험 배치
- 부족한 사실 질문
- 작성 또는 보완
- 수정 라운드
- 문항 간 중복검사
- 최종검수
- 면접 예상 질문

내부 비용 통제:
- 지원 문항 최대 개수
- 입력 문서 용량
- 총 입력 텍스트 길이
- 정상적인 수정·재첨삭 라운드
- 활성 기간
- 동일 질문 반복 감지
- 취업 지원 범위를 벗어난 요청 제한

사용자 화면에 `남은 질문 7회`를 공격적으로 표시하지 않는다.
구체적인 제한 수치는 실제 API 원가와 사용행태를 확인한 뒤 정한다.

7. 결제 전 작성 단계 자동 확인
======================================================================

결제 전에 사용자가 `어떤 단계인지 모르겠어요`를 선택하면:

- 텍스트 직접 입력
- PDF, DOCX, TXT 파일 선택
- 목표 글자 수 입력

을 제공할 수 있다.

이 단계에서는:
- 브라우저 안에서만 텍스트를 읽는다.
- 서버에 업로드하지 않는다.
- Supabase에 저장하지 않는다.
- OpenAI API를 호출하지 않는다.
- 작성량과 목표 분량 비율로 임시 추천한다.

안내:

`분량을 기준으로 한 임시 추천이며 내용의 완성도는 결제 후 분석합니다.`

======================================================================
8. ChatGPT에게 설명할 내용
======================================================================

MOOA Resume이 이 구조를 선택한 이유는 단순히 AI 호출 비용을 줄이기 위해서만이 아니다.

첫째, QUICK과 PRO가 해결하는 문제가 다르다.

QUICK은 이미 쓴 글을 고치는 상품이고,
PRO는 기업 지원서 전체를 하나의 프로젝트로 완성하는 상품이다.

둘째, 같은 PRO라도 사용자의 현재 상태에 따라 필요한 작업이 다르다.

CREATE는 소재와 사실을 먼저 찾아야 하고,
BUILD는 부족한 근거를 보강해야 하며,
POLISH는 기존 문장을 보존하면서 최종 교차검수해야 한다.

셋째, CREATE를 무제한 채팅으로 만들면 비용뿐 아니라 품질과 사실 추적이 불안정해진다.

따라서 대화형 UI는 사용하되 진행 단계, 선택한 경험, 확인된 사실, 답변, 개요와 초안은 구조화해 저장한다.

넷째, 가격은 사용시간이나 메시지 수가 아니라 사용자가 구매하는 결과물의 범위를 기준으로 설명한다.

QUICK:
`작성한 글을 제대로 고쳐드립니다.`

PRO:
`무엇을 쓸지부터 함께 찾고, 기업 지원서 한 건을 최종 제출까지 완성합니다.`

9. 현재 최종 요약
======================================================================

CREATE
- QUICK X
- PRO O
- Guided Interview
- 경험 확인 → 사실 승인 → 개요 → 초안 → 최종검수

BUILD
- QUICK O: 현재 글 중심 첨삭
- PRO O: 공고·이력서까지 활용한 내용 강화

POLISH
- QUICK O: 빠른 최종 첨삭, 기본 추천
- PRO O: 공고·이력서·경력자료 전체 교차검수

중요:
POLISH의 PRO가 CREATE의 PRO 화면으로 이동하면 안 된다.
같은 상품 가격을 사용하지만 WritingMode별 시작 플로우를 분리해야 한다.
